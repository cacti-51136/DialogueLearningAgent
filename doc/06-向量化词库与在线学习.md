# 06 · 向量化词库与在线学习（子系统）

> 本篇是 [02 · 三层关键词权重模型](./02-三层关键词权重模型.md) 的**扩展子系统**，落实用户在评审中提出的词库设计：
> 三个词库用**多维 embedding 向量化模型**存储"跨层角色关键词之间的关联关系"；
> 对话中由**大模型实时增删改**当前场景下的用户/Agent 关键词；
> 当大模型给出用户/ Agent 关键词更新时，**本地词库模型权重按学习率 + 损失函数**更新；
> 最终效果是**双反馈回路**：用户肖像越聊越丰富 → Agent 关键词越贴合理想；Agent 回复后用户满意度 → 反向调整 Agent 关键词权重。

## 0. 边界澄清（重要）

为避免与 [01 §1.2](./01-架构设计总览.md) 冲突，先划定：

| 本子系统**做**的 | 本子系统**不做**的（与既有设计一致） |
|---|---|
| 把**关键词本身**向量化，建模词与词的关联 | 对**对话历史消息**做语义向量检索 / RAG（**此项已由 [07 · 对话历史冷热记忆](./07-对话历史冷热记忆(LangGraph+RAG).md) 以 LangGraph 单独实现**；二者是独立向量空间，互不替代） |
| 训练一个**很小的本地关联模型**（d×d 双线性矩阵） | **微调大模型 LLM**（人格调节仍只走 Prompt） |
| 用 LLM 抽取结果作为**监督信号**更新本地模型 | 让 LLM 自由造词、脱离词表（仍走白名单 + 审核） |

一句话：**向量化的是"词库"，不是"聊天记录"；被训练的是"关联矩阵"，不是"大模型"。** 全程离线、纯 numpy、无 GPU、无额外大依赖。

---

## 1. 设计目标

把"词库自动演化"（[02 §11](./02-三层关键词权重模型.md)）从"LLM 建议 + 人工审核"升级为**可自学习的关联结构**：

1. **关联可计算**：任意两个关键词（可跨层）之间有一个可学习的关联强度，而不只是手写耦合规则。
2. **冷启动可生成身份**：新场景开始时，仅靠初始场景权重，用本地向量化模型为 Agent 生成一组**初始身份关键词**，无需立即调 LLM。
3. **实时增删改**：对话中由 LLM 判断并产出对当前场景用户/Agent 关键词的 `add / update / delete` 操作，带护栏即时生效。
4. **在线学习**：LLM 的用户关键词预测、Agent 关键词操作、用户满意度，都转化为**监督信号**，按**学习率 + 损失函数**更新本地关联模型。
5. **双反馈回路收敛**：用户肖像丰富度 ↑ → Agent 关键词贴合度 ↑；满意度反馈 → Agent 风格向"让用户满意"收敛。
6. **双运行模式**：固定场景模式（场景模板固定）与自动场景模式（LLM 实时判定并更新 L1 场景关键词 `scene_ops`）；并据场景权重由模型生成开场称呼、无权重时回退默认（见 [01 §6 D19–D20](./01-架构设计总览.md)、[02 §3.5/§12](./02-三层关键词权重模型.md)）。

## 2. 本地向量化模型（LVM, Local Vectorization Model）

### 2.1 关键词基础向量 `e_k`（冻结，不训练）

每个关键词 `k` 有一个基础向量 `e_k ∈ R^d`，`d` 默认 **64**。

- **语义热启动（可选）**：若配置了 `DLA_LVM__BACKBONE`（如 `paraphrase-multilingual-L12-v2`，支持中英混合），用本地推理把 `label + " / " + description` 编码后归一化作为 `e_k`。模型在**启动时下载一次、之后完全离线**，lazy import，缺失不报错。
- **随机回退（默认）**：未配置 backbone 时，`e_k = rng.normal(0, 0.1, d)`，其中 `rng = np.random.default_rng(hash(keyword_id))`，**按 keyword_id 确定性初始化**（同一词每次启动向量一致，可复现）。

> **`e_k` 冻结不训练**。语义锚点一旦被训练污染，关联就会失真。学习只发生在下面的关联矩阵 `M_r` 上——这等价于"冻结主干 + 可训练线性头"，是稳定且经典的做法。

### 2.2 关联矩阵 `M_r`（可训练，"本地模型权重"）

定义 **K 个关系头（relation head）**，每个头是一个双线性矩阵：

| 关系头 `r` | 含义 | 两端 |
|---|---|---|
| `scene_agent` | 场景 → Agent 人格映射 | L1 ↔ L3 |
| `user_agent` | 用户状态 → Agent 人格映射 | L2 ↔ L3 |
| `user_user` | 用户状态之间的共现 | L2 ↔ L2 |
| `scene_constraint` | 场景 → 硬约束映射 | L1 ↔ `constraint` |

每个头 `r` 持有：

```
M_r ∈ R^{d×d}        # 关联矩阵，可训练。初始化 M_r = α·I，α=0.1（初始近零关联）
c^r  : R^{|K|}       # 每词偏置（可选，默认 0）
```

> **"多维"的两层含义**：① 每个关键词活在 `R^d`（d 维向量空间）；② 存在 **K 个关系头**，分别刻画不同**关系类型**的关联。二者共同构成"多层场景角色各个关键词之间的关联关系"。

### 2.3 关联打分（bilinear score）

关键词 `i` 与 `j` 在关系头 `r` 下的关联分：

```
S_r(i, j) = ( e_iᵀ · M_r · e_j + c_i^r + c_j^r ) / d        # 除以 d 做数值稳定
```

当一端是**聚合上下文向量** `q`（多个词的加权和，见 §3）时退化为线性打分：

```
S_r(q, j) = ( qᵀ · M_r · e_j ) / d + c_j^r
```

用双线性形式而非余弦，是因为它的解析梯度极简（见 §6.3），且 `M_r = α·I` 初始化时 `S≈0`，即**初始没有任何偏置关联，一切从数据里学**——这是安全的冷启动默认值。

### 2.4 LVM 的参数总量与开销

- d=64，4 个关系头 → 约 `4 × (64×64 + 数百偏置) ≈ 16k` 个可训练参数。
- 一次梯度步 = 几个 `64×64` 矩阵的乘加，**微秒级**，纯 numpy，无 GPU。
- 模型文件（M_r + c^r + e_k 缓存）全量约 **数十 KB ~ 数百 KB**，直接随 SQLite 一起落库（见 [03 §2.10+](./03-数据模型与存储.md)）。

## 3. 新场景冷启动：为 Agent 生成身份关键字

新对话开始、尚无任何用户发言时（L2 仅有 preset）：

```
1. 取已解析的 L1 权重 { w1(k) }（来自场景模板 / 用户显式选择）
2. 构造场景上下文向量：  q = Σ_{k ∈ L1 活跃} w1(k) · e_k
3. 对场景下"允许出现的 L3 关键词候选集"每个 j：
       a_j = S_scene_agent(q, e_j)
       p_j = softmax_j(a_j / τ)          # τ = DLA_LVM__TEMP，默认 0.2
4. 取 p_j 最高的 Top-T（T = DLA_LVM__TOP_T_IDENTITY，默认 6）
   → 这组即 Agent 的【初始身份关键字】
```

**特点**：

- 完全**确定、离线、不调 LLM**，满足"根据最初的场景权重使用本地向量化模型为 agent 生成简单的身份关键字"。
- 初始 `M_r = α·I` 时 `a_j≈0`，分布接近均匀 → 身份关键字约等于"场景模板允许的全部候选里各取一点"，是保守的安全默认；随着对话推进 M_r 被训练，生成会越来越个性化。
- 生成的身份关键字**不直接覆盖** [02 §5.2](./02-三层关键词权重模型.md) 的规则基线，而是作为 L3 的**额外先验源** `p_agent` 参与融合（见 §5）。
- **自动模式下 L1 可能为空**：此时 `q` 退化为仅含 L2（冷启动基本无 L2），生成的身份关键字近似"模板候选均匀采样"。待 `scene_ops`（§4.4）建立 L1 后，身份生成才真正场景化；开场称呼在此阶段按 [02 §12](./02-三层关键词权重模型.md) 回退默认。

## 4. 对话中：大模型实时增删改词库

分析器（[02 §8](./02-三层关键词权重模型.md)）在每轮抽取之外，**额外产出三类结构化结果**：

```json
{
  "scene_ops": [
    { "op": "add",    "key": "scene.oral_practice", "intensity": 0.6,
      "reason": "用户提到想练口语、纠正发音" }
  ],
  "user_predictions": [
    { "key": "user_mood.curious", "intensity": 0.5, "depth": "shallow" }
  ],
  "agent_ops": [
    { "op": "update", "key": "agent_tone.encouraging", "delta": 0.15, "reason": "用户连续尝试，需鼓励" },
    { "op": "add",    "key": "agent_style.metaphor",
      "proposed_dimension": "agent_style", "kind": "scalar",
      "label": "风格·善用比喻", "render_template": "- 多用生活化的比喻解释概念",
      "conf": 0.6, "reason": "用户理解抽象概念吃力" },
    { "op": "delete", "key": "agent_role.strict_examiner", "reason": "当前氛围不适合考官角色" }
  ],
  "satisfaction": { "score": 0.7, "signal": "用户主动延伸话题，语气轻松", "based_on_turn": 7 }
}
```

### 4.1 用户肖像关键词：当前轮"浅预测"

`user_predictions` 只依据**当前这一轮的内容**做判断（`depth: shallow`），**不做跨轮深推**。它们走 [02 §4](./02-三层关键词权重模型.md) 既有的证据→置信度路径，是 L2 演化的常规输入。

### 4.2 Agent 关键词操作（当前场景工作集）

`agent_ops` 修改**当前会话的 L3 工作集**（场景模板定义的词 + 本轮运行中增删的词），带护栏：

| 操作 | 行为 | 护栏（任一违例 → 拒绝并记录 warn） |
|---|---|---|
| `update` | 对工作集权重的增量调整 | `|delta| ≤ 0.4`；目标词必须在本会话工作集内 |
| `add` | 新增候选词 | 走 [02 §11.4](./02-三层关键词权重模型.md) 的候选→审核流程；`render_template` 仅允许 `{label}`/`{value_text}`；非新维度才允许自动收编 |
| `delete` | 移除词 | **只能删 `auto_added` 或运行期新增的工作集词**；场景模板基础词受保护，不可被 LLM 删除 |

> 所有 `agent_ops` 落 `lexicon_ops` 表（见 [03 §2.11](./03-数据模型与存储.md)），可审计、可回放。

### 4.3 满意度信号

`satisfaction.score ∈ [-1, 1]`，由 LLM 依据"**Agent 回复之后、用户的下一轮发言**"判定（显式反馈如"谢谢，这个好"=高；"还是不懂"=低）。该信号是**后向反馈回路**的训练源（见 §7.2）。

### 4.4 场景关键词操作（自动模式）

`scene_ops` 是自动场景模式（[01 §6 D19](./01-架构设计总览.md)、[02 §3.5](./02-三层关键词权重模型.md)）下 L1 的实时更新通道，作用于**场景层关键词**（`layer=L1`，如 `scene.*`、`goal_agent.*`、`domain.*`）：

| 操作 | 行为 | 护栏（任一违例 → 拒绝并记录 warn） |
|---|---|---|
| `add` | 新增场景关键词 | 走 [02 §11.4](./02-三层关键词权重模型.md) 候选→审核流程；非新维度才允许自动收编；`render_template` 仅允许 `{label}`/`{value_text}` |
| `update` | 调整场景词强度 | `|delta| ≤ 0.4`；目标词必须在当前会话 L1 工作集内 |
| `delete` | 移除场景词 | 仅可删 `auto_added` 或运行期新增词；场景模板基础词受保护 |

与 `agent_ops` 的差异：它修改的是 **L1 舞台设定**而非 L3 人格。一旦 `scene_ops` 把 L1 建立到稳定状态，[02 §3.5](./02-三层关键词权重模型.md) 会给这些词设置较高等效初始证据，使其在后续对话中**不再随意漂移**（场景锁定）。

所有 `scene_ops` 同样落 `lexicon_ops` 表（`layer=L1`），与 `agent_ops` 共用审计与回放机制。

> 自动模式的前几轮：L1 尚空 → Agent 开场称呼回退默认（[02 §12](./02-三层关键词权重模型.md)），且 LVM 冷启动身份生成（§3）因缺 L1 暂退化为"模板候选均匀采样"；待 `scene_ops` 累积出 L1，二者同步转为场景化。**固定模式则全程跳过 `scene_ops`。**

## 5. 学习先验如何接入现有 L3 计算

[02 §5.2](./02-三层关键词权重模型.md) 的 L3 融合公式扩展为**三源融合**：

```
w3(k) = clamp(
           (1 - β - γ) · w3_rule(k)
         +      β      · w3_llm(k)
         +      γ      · p_agent(k),
         0, 1
        )
```

- `β`：LLM 精炼融合权重（既有，默认 0.3）。
- `γ`：本地向量化模型的**学习先验**融合权重，默认 **0.2**（`DLA_LVM__L3_PRIOR_GAMMA`）。
- `p_agent(k)`：由 LVM 对"当前上下文 q_t"打分得到的 Agent 关键词先验软分布：

```
q_t = Σ_{L1 活跃} w1·e  +  Σ_{L2 活跃} w2·e          # 场景 + 已积累的用户肖像
p_agent(k) = softmax_k( S_user_agent(q_t, e_k) / τ )
```

**这就是"用户肖像越丰富 → Agent 关键词越贴合"的工程实现**：随着 L2 关键词增多、`w2` 变大，`q_t` 越来越能代表"此刻的用户"，LVM 据此检索出的 Agent 关键词越来越准。

> **稳定性不被破坏**：融合后的 `w3` 仍走 [02 §7.4](./02-三层关键词权重模型.md) 的 Δ 滞回 + 冷却判定。学习率小、`γ` 小，人格不会因一次学习步就跳变。

## 6. 在线学习：损失函数与学习率

### 6.1 监督信号构造

每个（或每 N 个）对话轮，把下列信息转成训练样本 `(q, p^*)`：

- **来自 `agent_ops`**：对当前轮上下文 `q_t`（回复前），目标分布 `p^*` 由操作构造——
  - `update +δ` / `add` → 对应关键词目标分 `+δ`；`delete` → 目标分设为很低（接近 0）。
  - 把目标分做 softmax 得 `p^*`（软标签，保留相对强度，不直接 one-hot，更平滑）。
- **来自 `satisfaction`**（基于 turn t 的 Agent 回复）：该回复生效时的活跃 L3 关键词集 `A_t`。
  - `score > 0`：提升 `A_t` 中关键词在 `p^*` 的权重；`score < 0`：压低。

若一轮同时有 ops 与 satisfaction，目标 `p^*` 按权重叠加（satisfaction 权重默认 1.0，ops 默认 1.0）。

### 6.2 损失函数

```
ŝ_j      = S_user_agent(q, e_j) / τ                 # 模型预测分
ŝ_soft   = softmax_j(ŝ)                              # 预测软分布

L = L_ce + λ_rank · L_margin + λ_reg · L_decay

L_ce     = - Σ_j  p^*_j · log ŝ_soft_j                       # 软交叉熵：教"映射"
L_margin = mean_{j∈pos, k∈neg} max(0, m + ŝ_k - ŝ_j)         # 排序边界（可选，λ_rank 默认 0.1）
L_decay  = ||M_r||²_F / d²                                   # 权重衰减，防发散
```

超参默认：`τ=0.2`、`λ_rank=0.1`、`m=0.2`、`λ_reg=1e-4`。

### 6.3 解析梯度与更新（纯 numpy，无 autograd）

关键：双线性打分的解析梯度极简。

```
∂ŝ_j / ∂M_r = e_j · qᵀ            # 因为 ŝ_j = qᵀ M_r e_j = tr(M_r · e_j qᵀ)
∂L_ce / ∂M_r = Σ_j (ŝ_soft_j - p^*_j) · e_j qᵀ      # 经 softmax 链式法则
∂L_decay/∂M_r = 2 λ_reg M_r / d²
g = ∂L_ce/∂M_r + λ_rank · ∂L_margin/∂M_r + ∂L_decay/∂M_r

g ← clip(g, max_norm = DLA_LVM__GRAD_CLIP)          # 默认 1.0，防炸
# 带动量 SGD：
v ← μ·v - η·g                                          # μ = DLA_LVM__MOMENTUM=0.9
M_r ← M_r + v
# 学习率按步衰减：
η_t = η_0 / (1 + DLA_LVM__LR_DECAY · step)             # η_0 = DLA_LVM__LEARNING_RATE=0.01
```

偏置 `c^r` 梯度同理（对 `ŝ_j` 的偏导为 1），同步更新。

### 6.4 训练频率与回放

- 默认每轮（或每 `DLA_LVM__TRAIN_EVERY_N_TURNS` 轮）攒本轮回合样本，做一次小步更新。
- 维护**回放缓冲** `DLA_LVM__REPLAY_BUFFER`（默认 256）保留近期 `(q, p^*)`，每次更新在缓冲上做 1~3 个 epoch，缓解单点噪声与灾难性遗忘。
- 学习只在**本地关联模型**上发生；LLM 调用次数、Prompt 组装、稳定性判定均不变。

### 6.5 检查点与持久化

- 会话结束或每 N 轮：把 `M_r`、`c^r`、优化器动量 `v`、步数 `step` 写回 `lvm_relation_heads` / `lvm_state`（[03 §2.10/§2.13](./03-数据模型与存储.md)）。
- 启动时加载，**跨会话持续个性化**（这正是"越用越懂你"的载体）。
- `lvm_training_log` 记录每步 `loss / lr / 样本数`，供调试思维链展示（与 [04 §2.3](./04-交互层设计.md) 的 `--debug` 对接）。

## 7. 双反馈回路（最终效果）

```
┌─────────────── 回路 A：前向（用户肖像丰富 → Agent 贴合） ───────────────┐
│                                                                       │
│  场景权重 ──LVM──▶ Agent 初始身份关键字（冷启动，确定性）              │
│       │                                                               │
│       ▼                                                               │
│  用户在对话中发言 ──LLM 浅预测──▶ L2 关键词证据累积                    │
│       │                                                               │
│       ▼                                                               │
│  上下文 q_t = Σ(L1)+Σ(L2) 越来越"像这个用户"                          │
│       │                                                               │
│       ▼                                                               │
│  LVM 检索 q_t → p_agent 越来越准 → γ 融合进 w3 → Agent 关键词         │
│       │                                                               │
│       └──────── 越来越符合"用户理想对话方式" ◀───────────────────────│
└───────────────────────────────────────────────────────────────────────┘

┌─────────────── 回路 B：后向（满意度 → Agent 权重收敛） ────────────────┐
│                                                                       │
│  Agent 回复（携带一组活跃 L3 关键词 A_t）                              │
│       │                                                               │
│       ▼                                                               │
│  用户下一轮反应 ──LLM 判定──▶ satisfaction.score ∈ [-1,1]             │
│       │                                                               │
│       ▼                                                               │
│  构造成对目标 (q_{t-1}, p^*：A_t 内关键词随 score 升降)              │
│       │                                                               │
│       ▼                                                               │
│  损失函数 L 对 M_r 求解析梯度 → 学习率 η 更新                         │
│       │                                                               │
│       └──────── M_r 强化"让人满意的 Agent 关键词" ◀─────────────────│
└───────────────────────────────────────────────────────────────────────┘
```

两条回路共用同一套 `M_r` 参数：A 回路让"**谁在对面**"被学进去，B 回路让"**这样聊他满意吗**"被学进去。二者叠加，Agent 人格从"场景模板默认值"收敛到"**这个用户、这种风格、最满意**"的定点。

## 9. 风险与权衡

| 风险 | 影响 | 缓解 |
|---|---|---|
| 随机初始化下关联学不出来 | 冷启动期 Agent 身份偏模板化 | 可选 backbone 热启动；`α·I` 初始化保证不发散；γ 默认小，主权重仍由规则兜底 |
| 单用户过拟合到早期坏信号 | 人格固化 | 回放缓冲 + 权重衰减 + 学习率衰减；`M_r` 可 `dla lvm reset` 一键复位 |
| 在线更新引入人格抖动 | 体验倒退 | 小学习率 + 梯度裁剪 + γ 小 + Δ 滞回兜底 |
| LLM 的 `add/delete` 滥用 | 词库污染 | §4.2 护栏 + 审核流程 + `lexicon_ops` 全量审计 |
| 关联矩阵跨场景串味 | A 场景学到的关联污染 B 场景 | 关系头按 `(scenario_id)` 可隔离；默认全局共享但带场景上下文向量 q，天然区分 |
| 调试不可见、变成黑箱 | 违背"可解释优先"原则 | `lvm_training_log` + 调试思维链展示每步 loss 与 top 变化词 |
