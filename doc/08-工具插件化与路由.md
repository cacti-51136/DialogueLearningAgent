## 0. 背景与边界

Agent 可调用的**本地工具**会随项目发展越来越多：`recall_memory`（文档内检索，见 [07 §4.7](./07-对话历史冷热记忆(LangGraph+RAG).md)）、计算器、网络搜索、日历、代码执行、外部 API……若把它们硬编码进 `DialogueEngine`，引擎会迅速腐烂、且无法在不重启的前提下扩展能力。

**本文要解决的三个问题**：

1. 工具以**插件单元**组织，统一契约，便于第三方/社区贡献；
2. 支持**运行时热更新**（增 / 改 / 删工具能力），不重启进程、不中断进行中的对话；
3. 当 LLM 需要调用本地工具时，用**工具路由（Tool Router）**先粗筛候选再交给 LLM 选择，避免把所有工具 schema 全塞给模型导致 token 膨胀与选择质量下降。

**边界（重要）**：

- 工具是**编排层（Orchestration）**能力，**不属于权重引擎**（doc/02）。工具结果**只进 Prompt / 当前轮上下文**，**绝不参与 L1/L2/L3 权重计算**，也不写回 `turn_summary` 摘要链。
- 本文的"工具"指**本地可执行动作**（含对冷热记忆的只读检索 `recall_memory`）；与外部 LLM 的结构化抽取（`agent_ops` / `scene_ops` / `user_predictions`，doc/06）是两回事——后者是分析结果，不是可路由的工具。
- 插件热更新的"功能"指**工具实现本身**（如换一个更准的检索算法、新增一个计算器），**不是微调或改变 Agent 人格**。

## 1. 设计目标

| # | 目标 | 说明 |
|---|---|---|
| G1 | 统一工具契约 | 所有工具实现同一 `Tool` 协议（name / version / description / parameters_schema / execute），引擎与 UI 只认契约 |
| G2 | 插件即目录 | 一个插件 = 一个目录 / 一个包，零样板即可被扫描发现 |
| G3 | **原子热更新** | 进行中的对话用旧快照，新对话用新快照；加载失败自动回滚到上一个已知良好快照 |
| G4 | 路由减负 | LLM 每次只见 top-N 候选工具，而非全量 |
| G5 | 安全可控 | 参数 schema 强制校验、权限域隔离、只读工具默认开启、危险工具需显式 enable |
| G6 | 可观测 | 调试器能逐帧看到"路由候选集 → 选定工具 → 执行结果"；工具调用记入 `tool_log` |

## 2. 工具插件契约（Tool Protocol）

```python
from typing import Protocol, runtime_checkable

@runtime_checkable
class Tool(Protocol):
    name: str                      # 唯一且稳定，建议 DNS 反写风格：com.dla.recall_memory
    version: str                   # 语义化版本；LLM 调用与回放日志均记版本
    description: str               # 给 LLM 看的自然语言说明（路由与 function-calling 共用）
    parameters_schema: dict        # JSON Schema，execute 前强制校验
    is_readonly: bool              # True=只读（默认开启）；False=有副作用（需显式 enable）
    permission_scope: str          # 权限域，如 "memory.read" / "network" / "fs.write"

    def can_handle(self, intent_hint: str, ctx: ToolContext) -> float:
        """路由阶段调用：返回本工具对该意图的适配度 [0,1]。
        可用规则 / 关键词 / 意图 embedding 相似度实现。默认实现返回 0/1 二分。"""
        ...

    def execute(self, args: dict, ctx: ToolContext) -> ToolResult:
        """执行工具。args 已通过 parameters_schema 校验。"""
        ...

@dataclass
class ToolContext:
    session_id: str
    user_id: str | None
    clock: Clock
    repositories: RepositoryBundle     # 只读访问仓储（含冷热记忆）
    llm: LLMClient                     # 工具内部如需二次调用模型

@dataclass
class ToolResult:
    ok: bool
    content: str | list[DetailBlock]   # 注入当前轮上下文的内容
    meta: dict                         # 结构化回传（不进 Prompt）
    error: str | None
```

**插件单元约定**：插件目录 `tools/plugins/<name>/` 下暴露 `plugin.py`，其中定义 `TOOLS: list[Tool]`（或实现 `register(registry: ToolRegistry) -> None`）。引擎启动时扫描该目录并加载；也支持通过 `pyproject.toml` 的 `entry_points`（`dla.tools`）注册已安装发行包，便于 pip 安装式插件。

## 3. 插件生命周期与热更新

### 3.1 注册表（ToolRegistry）—— 原子快照

```python
class ToolRegistry:
    def __init__(self):
        self._snapshot: ToolSnapshot = ToolSnapshot({})   # 不可变快照

    def snapshot(self) -> ToolSnapshot:                   # 进行中对话持有引用，永不失效
        return self._snapshot

    def reload(self, plugin_name: str | None = None):
        new = self._build_next_snapshot(plugin_name)      # 新建独立快照
        new.validate()                                    # 校验契约/签名/冲突
        self._snapshot = new                              # 原子替换指针（GIL 下单操作即原子）
```

- **进行中的对话**在轮次开始处 `.snapshot()` 并持有该引用；热更新只替换指针，**不影响正在跑的对话**。
- **新对话**拿到的就是新快照。

### 3.2 热更新触发方式

| 触发 | 来源 | 说明 |
|---|---|---|
| 手动 | `dla tool reload <name>` | 运维/开发显式重载单个插件 |
| 文件监听 | `DLA_TOOLS__AUTO_RELOAD=watch` | 插件目录文件变更自动重载（开发期） |
| 远程控制 | 受控管理接口（M5 以后） | 生产环境灰度发布新插件版本 |

### 3.3 热更新三道安全闸

1. **加载即校验**：插件加载时做静态检查（签名/白名单/契约完整性），非法插件**拒绝加载**且不替换当前快照。
2. **灰度 shadow**：`DLA_TOOLS__HOTRELOAD_SHADOW=true` 时，新版本先以"影子"身份并行观测（记录会被选中/执行的日志，但不真正生效），确认无误再原子切换。
3. **失败回滚**：新快照 `validate()` 抛错或切换后短时间内异常率超阈 → 自动回滚到上一个 `tool_snapshot_last_good`，并在 `tool_log` 记告警。

### 3.4 版本化

工具以 `name@version` 标识。LLM 的每次工具调用在 `tool_log` 记版本号，配合 doc/07 的 checkpoint，**任意历史轮次可精确复现**（包括当时用的是哪个版本的工具）。

## 4. 工具路由（Tool Router）

### 4.1 问题

把所有工具 schema 全量喂给 LLM → ① token 膨胀（每个工具 description+JSON Schema 很贵）；② 选项越多 LLM 选择质量越差；③ 与场景无关的工具会干扰判断。

### 4.2 方案：两级路由

```
                  ┌──────────────── 一级：低成本路由（非 LLM） ────────────────┐
   当前上下文 ───▶ │ 场景 / 意图信号 / 活跃关键词 / 本轮用户提问 embedding      │
   (场景,L2,L3,    │  × 各工具 description embedding 相似度 + 规则加权          │
    用户问题)      │  → 候选集 top-N（默认 N=6）                               │
                  └────────────────────────────────────────────────────────────┘
                                          │ 仅候选集
                                          ▼
                  ┌──────────────── 二级：LLM 选择 ────────────────┐
   候选工具 schema + 场景说明 ──▶ LLM 决定：调用哪个 / 填什么参 / 不调用
                  └────────────────────────────────────────────────┘
```

- **一级路由实现可选**（由 `DLA_TOOLS__ROUTER` 切换）：
  - `always_all`：不做路由，全量给 LLM（调试/工具极少时）；
  - `rule`：基于场景与关键词的规则匹配（零成本、可解释）；
  - `embedding`：用户提问 embedding × 工具 description embedding 余弦，取 top-N（复用 doc/06 的向量化思路，本地、离线）；
  - `hybrid`（默认）：规则先过滤明显无关项，embedding 再精排。
- **二级 LLM 始终是最终裁决者**：候选集中 LLM 仍可选择"不调用任何工具"；若路由漏选但 LLM 强烈需要，可 `fallback=always_all`（受 `PROMPT_RATIO` 预算约束，日志告警）。
- **路由可解释**：调试模式下打印"一级候选集 + 命中理由 + 二级选定"。

### 4.3 与 LangGraph 的衔接

LLM 选定工具后进入 doc/07 的节点 ⑥ `handle_tools`——但执行器从"写死的 `recall_memory` 分支"改为**查询 `ToolRegistry.snapshot()` 按 `name` 派发执行**。节点的 `TOOL_MAX_LOOPS`（doc/07 §4.7，默认 2）不变，防死循环。

## 5. 与既有系统的集成

- **`recall_memory` 成为第一个内置插件示例**：原 doc/07 §4.7 的工具实现平移为 `tools/plugins/recall_memory/plugin.py`，对外仍暴露同名 `Tool`，走同一路由。`DLA_MEMORY__TOOL_*` 配置保留为该插件的私有参数。
- **结果边界复用 doc/07 护栏**：工具结果进 `detail_blocks` / 当前轮上下文，**不写回 `turn_summaries`、不参与 L1/L2/L3 权重**；只读、不修改记忆（除非工具显式声明写权限且已 enable）。
- **CLI 管理命令**（见 doc/04 §2）：
  - `dla tool list` —— 列出已加载插件 / 工具版本 / 启用状态
  - `dla tool describe <name>` —— 打印 description 与 parameters_schema
  - `dla tool reload <name>` —— 热重载指定插件
  - `dla tool enable|disable <name>` —— 启停（危险工具默认 disable）
- **调试思维链**（见 doc/04 §2.3）：在 ⑧ 之后（或并行）新增"工具路由帧"——展示候选集、选定工具、执行结果摘要。

## 6. 配置

```bash
# ---- 工具插件与路由（doc/08）----
DLA_TOOLS__ENABLED=true                   # 总开关
DLA_TOOLS__PLUGIN_DIR=tools/plugins       # 插件扫描目录
DLA_TOOLS__ROUTER=hybrid                 # always_all | rule | embedding | hybrid
DLA_TOOLS__ROUTER_TOP_N=6                # 一级路由候选集大小
DLA_TOOLS__AUTO_RELOAD=off               # off | watch(文件监听) | manual
DLA_TOOLS__HOTRELOAD_SHADOW=true         # 新版本先 shadow 观测再切换
DLA_TOOLS__MAX_CONCURRENT=4              # 单轮工具并发上限
DLA_TOOLS__FALLBACK_ALL_ON_MISS=true     # 路由漏选且 LLM 需要时回退全量（受预算约束）
```

## 7. 风险与权衡

| 风险 | 影响 | 缓解 |
|---|---|---|
| 热更新导致进行中对话状态不一致 | 行为错乱 | 原子快照 + 版本化；进行中对话持旧快照引用 |
| 恶意/缺陷插件 | 安全或崩溃 | 加载校验（签名/白名单/契约）+ 权限域隔离 + 危险工具默认 disable |
| 路由漏选关键工具 | 该用的没用上 | `FALLBACK_ALL_ON_MISS` + 漏选日志告警 |
| 工具执行超时/异常 | 卡顿或崩溃 | 超时熔断 + 异常降级（返回友好错误，不中断对话） |
| 插件热更新引入新 bug | 回归 | shadow 灰度 + 自动回滚到 last-good 快照 + `tool_log` 审计 |

## 8. 测试策略

| 测试 | 构造 | 断言 |
|---|---|---|
| 插件加载/卸载 | 提供合法/非法插件目录 | 合法者入快照；非法者拒绝加载且不替换 |
| 热替换 | 运行中持有旧快照引用，reload 新版本 | 旧引用仍可调用旧版；新快照为新版；异常时回滚 |
| 路由召回 | 固定意图 + 已知工具集（占位 embedding） | top-N 候选集命中预期工具 |
| 端到端（recall_memory） | 假 LLM 发起 tool_call | 经 `ToolRegistry` 派发，返回 top-K 原文，重生成拿到细节；超 `TOOL_MAX_LOOPS` 被停 |
| 参数校验 | 传入非法 args | 执行前被 schema 校验拦截，不进 execute |
