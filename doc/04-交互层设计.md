# 04 · 交互层设计（CLI / API / PyQt）

## 1. 总原则

三个交互端共用**同一个核心引擎**，差异只在外壳。

引擎对外暴露**同步与异步双入口**（决策 D8）：

```python
class DialogueEngine:
    # 异步入口：CLI 与 API 使用，支持流式 token 回调
    async def astream_reply(
        self, session_id: str, user_text: str,
        on_token: Callable[[str], Awaitable[None] | None],
    ) -> TurnResult: ...

    # 同步生成器入口：Qt 使用，在 QThread 中迭代，不碰 asyncio
    def stream_reply_sync(
        self, session_id: str, user_text: str,
    ) -> Iterator[TurnEvent]: ...
```

`TurnEvent` 是一个事件流：`TokenEvent` / `WeightUpdateEvent` / `PersonaChangeEvent` / `DoneEvent` / `ErrorEvent`。

**为什么不让 Qt 直接用 async**：Qt 的事件循环与 asyncio 的事件循环需要 `qasync` 之类的桥接才能共存，多一层不稳定因素。而 Qt 有成熟的 `QThread` + Signal 机制解决同样的问题。让两端各用各的原生方案，比强行统一更稳。同步入口内部用 `asyncio.run()` 在独立线程中驱动，对外表现为普通生成器，**零事件循环冲突**。

### 3.1 SSE 事件格式

```
event: token
data: {"text": "I hear"}

event: weights
data: {"layer": "L2", "items": [...]}

event: persona_change
data: {"delta": 0.21, "action": "rebuilt", "diff": [...]}

event: done
data: {"turn": 6, "usage": {...}}
```

前端约定：**4xx 不重试，5xx 自动重试最多 3 次；网络失败显示离线提示。** 错误体统一结构：

```json
{ "error": { "code": "LLM_UPSTREAM_ERROR", "message": "上游服务暂时不可用", "request_id": "..." } }
```

**绝不返回堆栈与内部路径。**

### 3.2 安全头与 CORS

- CORS 使用**显式来源白名单**，生产禁用 `*`。
- 统一响应头：`X-Content-Type-Options`、`X-Frame-Options`、`Referrer-Policy`、`Cache-Control: no-store`。
- 单用户工具不加认证；若后续暴露到公网，必须前置 API Key 中间件。

### 4.2 线程模型

Qt 的铁律：**主线程只做 UI，任何网络/数据库操作都不许在主线程**。

```python
class StreamWorker(QThread):
    token_received   = Signal(str)          # 流式 token
    weights_updated  = Signal(object)       # 权重快照 → 刷新右侧面板
    persona_changed  = Signal(object)       # 人格变更 → 状态栏提示
    failed           = Signal(str)          # 错误 → 弹窗
    finished_turn    = Signal(object)

    def __init__(self, engine, session_id, text):
        super().__init__()
        self._engine = engine
        self._session_id = session_id
        self._text = text
        self._stop_requested = False

    def run(self):
        try:
            for event in self._engine.stream_reply_sync(self._session_id, self._text):
                if self._stop_requested:
                    break
                if isinstance(event, TokenEvent):
                    self.token_received.emit(event.text)
                elif isinstance(event, WeightUpdateEvent):
                    self.weights_updated.emit(event.snapshot)
                elif isinstance(event, PersonaChangeEvent):
                    self.persona_changed.emit(event.change)
                elif isinstance(event, ErrorEvent):
                    self.failed.emit(event.user_message)
        except Exception as exc:            # 兜底，绝不让线程静默死亡
            self.failed.emit(str(exc))

    def stop(self):                          # 用户点"停止生成"
        self._stop_requested = True
```

要点：

- **跨线程只能通过 Signal 更新 UI**，绝不在 worker 里直接操作 Widget（Qt 会崩）。
- **停止生成**：worker 内检查标志位并提前 break，同时关闭底层 HTTP 流，避免连接泄漏。
- **防抖刷新**：token 到达频率很高，UI 用 `QTimer`（约 30ms）合并刷新，避免高频重绘卡顿。
- **线程生命周期**：worker 设为 `MainWindow` 的子对象或在 `finished` 信号里 `deleteLater()`，防止悬挂指针。
- **输入锁**：生成期间禁用发送按钮，worker 结束后恢复；异常路径也要恢复（`finally` 语义靠信号槽保证）。

### 4.3 权重面板实现

用 `QTreeWidget` + 自定义 `QStyledItemDelegate` 绘制权重条。更新策略是**增量 diff** 而非整体重建：只刷新数值变化的行，避免长对话时的闪烁与卡顿。

提供"变化高亮"：本轮权重变动超过阈值的行，短暂高亮背景色并标注增量（`+0.35`），让用户一眼看到"AI 刚刚调整了什么"。

### 4.4 思维链面板（调试可视化）

为落实"调试模式展示思维链"的确认，右侧面板下方增加可折叠的**思维链（Chain-of-Thought）**页签，与权重页签并列：

- **逐步展开**：每一轮以可折叠树形展示 ①触发判定 → ②启发式 → ③LLM 抽取 → ④更新 L2 → ⑤规则 gate 求值 → ⑥稳定性 Δ → ⑦Prompt 组装 → ⑧压缩摘要/记忆 → ⑨工具路由/调用（doc/08）→ ⑩重复护栏（doc/01 §9）。点击任意一步显示该步的输入/输出片段；⑧ 节点展示本轮回传的 `turn_summary`、下一轮将注入的摘要链预览，以及是否发起过 `recall_memory` 工具调用（附取回的原文片段数）；⑩ 节点展示 `detect_repetition` 的相似度 / 自重复 n-gram 判定结果，以及命中后的反重复重试 / 轻量兜底路径。
- **候选词提示**：若本轮 LLM 发现 `novel_concepts`，在思维链节点旁显示一个「＋候选」徽标，点击可预览候选详情并直接审批（界面内 `approve`/`reject`，等价于 `dla keyword` 命令）。
- **Prompt 预览**：思维链末节点可展开当轮完整 System Prompt（仅调试模式可见），支持复制。
- **实时性**：复用 StreamWorker 已有的 Signal 机制，新增 `chain_step` 信号逐节点推送；同样遵守"worker 只发信号、主线程更新 UI"的铁律，且用 `QTimer` 防抖。
- **不干扰正常对话**：思维链页签默认折叠，仅 `--debug` 或界面设置开启时填充内容；日常使用零感知。

### 4.5 关键交互细节

| 场景 | 处理 |
|---|---|
| 首屏无会话 | 引导选择**运行模式**（固定/自动/自由）与**场景模板**（下拉来自内置预设库 [09 预设场景与角色模板库](./09-预设场景与角色模板库.md)，默认高亮 `oral_practice`）；**自由模式**需用户填写一段"场景描述"，LLM 据此生成三层基础关键词后再开始 |
| 未配置 API Key | 启动即弹配置向导，而不是等到报错 |
| 生成中关闭窗口 | 先请求 worker 停止并等待（超时 2s 强退），避免 SQLite 写入中断 |
| 人格显著切换（Δ ≥ τ_notify） | 对话区插入一条系统提示气泡："我放慢一点节奏，我们多练几句" |
| LLM 分析静默失败 | 无任何感知；权重面板顶部显示一个小灰点提示"本轮分析未生效" |
| 长对话 | 消息区采用懒加载，只渲染最近 N 条，滚动到底部时再加载更早内容 |

### 4.6 分发

后续可用 PyInstaller 打包（`dla-qt.spec`）。注意：
- Qt 插件需随包分发，PyInstaller 的 Qt hook 会自动处理。
- 若改用 PySide6，打包流程基本一致——这正是 `qt_compat` 抽象层的又一次收益。
- 打包前再确认一遍许可证选择（见 [01 文档 §3.1](./01-架构设计总览.md)）。
