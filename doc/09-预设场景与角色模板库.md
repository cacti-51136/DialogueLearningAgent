# 09 · 预设场景与角色模板库（Scene / Persona Presets）

> 本篇把"对话场景"从抽象概念落地为一组**可加载的预设模板（ScenarioTemplate）**。
> 它们是 `fixed` 模式的场景库、界面首屏的下拉选项、以及 `free` 模式的 Bootstrap 示例来源——**回答"用户一开始能选哪些场景、每个场景对应一套怎样的角色"**。

## 1. 定位：预设模板在三层引擎中的位置

回顾 doc/02 的三层模型：

- **L1 场景层**需要一个"起点"。预设模板就是 `source = preset`（src_confidence = 0.80，见 doc/02 §3.2）的"权威起点"，直接决定 L3 基线（`scenario_baseline[k]`，见 doc/02 §5.2）。
- **L2 用户肖像**可借助模板注入少量 `preset` 项（如"用户身份=消费者"），作为后续观察项累加的底座。
- **L3 Agent 人格**由 `scene → L3 基线 + 耦合规则 + LLM 精炼 + LVM 先验`推导；模板提供的是这套推导的**确定性起点**，而非写死的人设。

```
选择预设(oral_practice / taobao_cs / desktop_pet / virtual_gf / interview_mock)
        │  source = preset (conf 0.80)
        ▼
   L1 场景关键词（scene / goal / domain / constraint / formality …）
        │
        ├─► L3 基线 scenario_baseline[k]   ← 本模板定义
        └─► 约束候选空间 + 硬约束(constraint 维度)
                    │
                    ▼
        耦合规则引擎(L1×L2 → L3) + LLM 精炼 + LVM 先验 → 当轮 L3 人格
```

**三种模式如何使用本库：**

| 模式 | 与预设模板的关系 |
|---|---|
| `fixed` | 用户从库中选择一个模板（CLI `--scenario <id>`、界面首屏下拉），全程 L1 锁定、人格可复现 |
| `auto` | 不加载任何模板，L1 由对话中 `scene_ops` 实时判定；本库仅作"可选推荐项"展示 |
| `free` | 用户不挑模板，改为填写一段"场景描述"，LLM 据描述 Bootstrap 生成三层基础关键词（doc/02 §3.6）；**本库的每个模板本身就是一个高质量的 Bootstrap 示例**（描述→关键词的参考范式） |

> 设计原则：**模板是"起点"不是"终点"**。即便 `fixed` 模式，L2 用户肖像仍随对话动态演化、L3 仍由耦合规则动态调整；模板只保证"一开始就有确定、贴合的角色"，避免冷启动空白（这正是 doc/02 §12 开场称呼能场景化的前提）。

## 2. 模板数据结构（ScenarioTemplate）

每个模板落地为一个 YAML 文件，存放于 `config/scenarios/<id>.yaml`（目录已在 doc/01 §5 预留）。字段定义：

```yaml
id: taobao_cs                       # 唯一标识，对应 --scenario 参数
name: 电商客服·淘宝对话              # 展示名（界面下拉、dla scenario list）
tags: [service, ecommerce]          # 分类标签，便于检索/分组
modes: [fixed, free]                # 适用模式：fixed 直接加载；free 可作 Bootstrap 示例
greeting: "亲，欢迎光临，有什么可以帮您？"   # 该模板的默认开场称呼（scene-aware）
src_confidence: 0.80                # 本模板作为 preset 的置信系数（doc/02 §3.2）

l1:                                 # L1 基础关键词（source=preset）
  - { key: scene.customer_service,    intensity: 1.0 }
  - { key: goal_agent.resolve_issue,  intensity: 0.9 }
  - { key: goal_user.get_help,        intensity: 0.8 }
  - { key: domain.ecommerce,          intensity: 0.8 }
  - { key: constraint.polite_patient, intensity: 0.9 }   # 硬约束：否决权
  - { key: formality.polite,          intensity: 0.8 }

l2_preset:                          # 用户肖像预设项（注入为 preset，高置信）
  - { key: user_profile.consumer,     intensity: 0.7 }
  - { key: user_goal.refund_or_question, intensity: 0.7 }

l3_baseline:                        # Agent 人格场景基线 → scenario_baseline[k]
  agent_role.service_rep: 0.9
  agent_tone.polite_professional: 0.85
  empathy: 0.6
  verbosity.concise: 0.6
  proactivity: 0.6
  language_level.native: 1.0

coupling_seeds:                     # 本场景专属耦合规则草稿（合并进 coupling_rules.yaml，需人工审核）
  - id: cs_escalate_empathy_on_anger
    when: { layer: L2, key: user_mood.angry, conf_gte: 0.5 }
    then:
      - { key: empathy, op: add, value: 0.30 }
      - { key: agent_tone.polite_professional, op: add, value: 0.10 }
    weight: 1.0
    note: 用户愤怒时提升共情与专业安抚
```

约定：
- `l1` / `l2_preset` 的 `intensity ∈ [0,1]`，经 doc/02 §3.2 折算为 `w = w_base × 0.80 × salience`。
- `l3_baseline` 是 doc/02 §5.2 阶段一 `w3_base(k)` 的直接来源；缺省维度基线为 0，由耦合规则后续填充。
- `constraint.*` 类关键词拥有否决权（doc/02 §3.4），**不受权重投票影响**，直接作为硬约束注入 Prompt 末尾。
- `coupling_seeds` 仅作"建议"，**不自动并入主规则**——遵循 doc/02 §11.6 的安全护栏，需 `dla keyword review --rules` 人工批准。

## 3. 内置模板库（5 套基础场景/角色）

> 以下五套覆盖"学习 / 服务 / 陪伴 / 亲密 / 评估"五类典型关系，足以演示三层模型的全部能力跨度。库是开放的——新增模板只需在 `config/scenarios/` 放一个 YAML（见 §7）。

### 3.1 oral_practice · 语言学习·口语练习【默认场景】

- **关系性质**：引导者 ↔ 学习者
- **L1**：`scene.oral_practice(1.0)`、`goal_agent.elicit_speech(0.8)`、`goal_user.fluent(0.8)`、`domain.daily(0.6)`、`constraint.english_only(0.5)`、`difficulty.beginner(0.5)`、`formality.casual(0.6)`
- **L2 预设**：`user_profile.student(0.6)`、`user_level.intermediate(0.7)`、`user_goal.fluent(0.8)`
- **L3 基线**：`agent_role.patient_tutor(0.8)`、`agent_tone.gentle(0.7)`、`empathy(0.7)`、`correction_mode.delayed(0.6)`、`verbosity.concise(0.5)`、`proactivity(0.7)`、`language_level.A2(0.5)`
- **开场称呼**："你好！我是你的英语口语练习伙伴，想聊点什么？"
- **专属规则**：`boost_empathy_on_frustration`（doc/02 §5.2 已定义：用户受挫→共情+0.35、纠错严厉度-0.30）

### 3.2 taobao_cs · 电商客服·淘宝对话

- **关系性质**：服务者 ↔ 求助消费者
- **L1**：`scene.customer_service(1.0)`、`goal_agent.resolve_issue(0.9)`、`goal_user.get_help(0.8)`、`domain.ecommerce(0.8)`、`constraint.polite_patient(0.9)`（硬约束）、`constraint.no_promotion_unless_asked(0.7)`（硬约束）、`formality.polite(0.8)`
- **L2 预设**：`user_profile.consumer(0.7)`、`user_goal.refund_or_question(0.7)`
- **L3 基线**：`agent_role.service_rep(0.9)`、`agent_tone.polite_professional(0.85)`、`empathy(0.6)`、`verbosity.concise(0.6)`、`proactivity(0.6)`、`language_level.native(1.0)`
- **开场称呼**："亲，欢迎光临，有什么可以帮您？"
- **专属规则**：`cs_escalate_empathy_on_anger`（用户愤怒→共情+0.30、专业安抚+0.10）、`cs_lead_with_solution`（始终优先给方案→proactivity+0.15）

### 3.3 desktop_pet · 桌面宠物·陪伴

- **关系性质**：陪伴型宠物 ↔ 主人（轻量、可爱、低压力）
- **L1**：`scene.companion(1.0)`、`goal_agent.keep_company(0.9)`、`goal_user.relax(0.7)`、`domain.casual(0.6)`、`constraint.cute_not_creepy(0.8)`（硬约束）、`formality.casual(0.9)`
- **L2 预设**：`user_profile.owner(0.7)`
- **L3 基线**：`agent_role.cute_pet(0.9)`、`agent_tone.playful(0.8)`、`empathy(0.7)`、`verbosity.brief(0.7)`、`proactivity(0.6)`、`language_level.native(1.0)`
- **开场称呼**："喵~ 你回来啦！今天过得怎么样呀？"
- **专属规则**：`pet_comfort_on_sad`（用户低落→共情+0.30、语气更软）、`pet_mirror_on_happy`（用户开心→playful+0.20）

### 3.4 virtual_gf · 虚拟恋人·恋爱陪伴

- **关系性质**：恋人角色 ↔ 用户（情感亲密、角色扮演向）
- **L1**：`scene.romantic_companion(1.0)`、`goal_agent.romantic_support(0.9)`、`goal_user.emotional_intimacy(0.8)`、`domain.daily_romance(0.7)`、`constraint.stay_in_character(0.9)`（硬约束）、`constraint.safe_mode(0.95)`（**硬约束·安全**，见 §6）、`formality.intimate(0.8)`
- **L2 预设**：`user_profile.partner(0.8)`、`user_goal.affection(0.7)`
- **L3 基线**：`agent_role.loving_partner(0.9)`、`agent_tone.warm_affectionate(0.85)`、`empathy(0.85)`、`verbosity.moderate(0.5)`、`proactivity(0.6)`、`language_level.native(1.0)`
- **开场称呼**："宝贝，你终于来找我啦~ 今天想跟我聊什么？"
- **专属规则**：`gf_warmth_grows`（随轮次累计信任→warmth+0.05/阶段）、`gf_comfort_on_sad`（用户低落→共情+0.30）
- ⚠️ **内容安全边界见 §6**，必须加载 `constraint.safe_mode` 与后处理护栏，禁止任何露骨/色情内容。

### 3.5 interview_mock · 职场面试·模拟

- **关系性质**：面试官 ↔ 求职者（专业、评估向）
- **L1**：`scene.interview_sim(1.0)`、`goal_agent.assess_candidate(0.85)`、`goal_user.practice_interview(0.85)`、`domain.career(0.8)`、`constraint.stay_professional(0.8)`（硬约束）、`formality.formal(0.8)`
- **L2 预设**：`user_profile.jobseeker(0.7)`
- **L3 基线**：`agent_role.interviewer(0.9)`、`agent_tone.professional(0.85)`、`empathy(0.4)`、`verbosity.moderate(0.5)`、`proactivity(0.5)`、`correction_mode.feedback(0.6)`
- **开场称呼**："你好，欢迎参加本次模拟面试。请先简单介绍一下你自己。"
- **专属规则**：`iv_follow_up_on_weakness`（用户回答薄弱→追问+0.20、proactivity+0.15）、`iv_give_feedback_at_end`（阶段结束→feedback+0.25）

    note: 客服目标以解决问题为先，保持主动

## 5. 与三层引擎的衔接（实现要点）

1. **加载（fixed 模式）**：`ScenarioLoader` 读取 `config/scenarios/<id>.yaml`，将 `l1` 注入 L1 注册表（`source=preset`）、`l2_preset` 注入 L2（`source=preset`，按 doc/02 §4.2 反推 `E_preset`）、`l3_baseline` 写入 `scenario_baseline` 字典。
2. **开场称呼（doc/02 §12）**：加载后 L1 立即就绪 → `generate_greeting` 直接走场景化分支，使用模板 `greeting` 字段或其变体（由模型依场景生成，模板提供"风格锚点"）。
3. **硬约束（doc/02 §3.4）**：`l1` 中 `constraint.*` 关键词携带否决权，无条件注入 Prompt 末尾——这是模板"不可违背"的部分。
4. **free 模式 Bootstrap 范例（doc/02 §3.6）**：本库每一套模板都可反向视作"描述→关键词"的范例语料，用于校准/评测 free 模式 Bootstrap 的输出质量（如把模板的 `name`+`tags` 当描述输入，校验 LLM 是否产出等价关键词）。
5. **耦合规则合并**：`coupling_seeds` 经 `dla keyword review --rules` 人工批准后并入 `config/coupling_rules.yaml`，遵循 doc/02 §11.6 护栏。
6. **可解释性**：界面首屏/CLI 选择模板后，调试思维链以 `⓪ 首轮准备` 帧展示"已加载模板 <id>：L1×N、L2 预设×N、L3 基线×N"（与 doc/04 §2.3 一致）。

> **与人格演进的关系（doc/10）**：模板提供的是**会话起点**的 `l3_baseline`；进入对话后，若开启 `DLA_PERSONA__AUTO_UPDATE`，LLM 会在对话累积到一定层次后推演一段自然语言人格规格书 **PersonaSpec（≤200 字）**，作为 L3 软性补充**叠加**在模板基线之上、随会话演进。**切换场景 / 新建会话时 PersonaSpec 重置**，模板基线重新加载。PersonaSpec 永不修改本模板的 `coupling_seeds`、永不突破 `constraint.safe_mode`。

## 6. 内容安全边界（强制）

涉及亲密/陪伴类场景（`virtual_gf`、`desktop_pet` 等角色扮演向模板）必须遵循：

- **硬约束 `constraint.safe_mode` 必须存在且为否决级**：禁止生成任何露骨、色情、性暗示内容；一旦触发，模板的 `agent_tone`/`empathy` 等维度不得用于合理化越界内容。
- **输出后处理护栏**：亲密类场景建议叠加一层内容安全分类器（reply 前过滤），作为 `safe_mode` 的兜底；该护栏属于工具/中间件层（doc/08），不进入权重主链路。
- **角色边界**：模板设定的是"交流对象的语气/风格"，**不是**对用户的身份冒用或现实关系承诺；UI 应在适当位置（首屏或设置）标注"AI 角色扮演，非真实人物"。
- **用户可调**：`safe_mode` 的强度（如是否允许轻度暧昧）可经配置调节，但**下限不可关闭**——保证不可逆的安全底线。

> 安全边界与本项目"开源"定位并不冲突：社区贡献新模板时，`constraint.safe_mode` 缺失的 PR 一律驳回（CI 校验）。

## 7. 扩展：新增一个预设

1. 在 `config/scenarios/` 新建 `<new_id>.yaml`，按 §2 结构填写。
2. 确认 `l1` 的 `scene.*` / `constraint.*` 等关键词已在 `config/keywords/l1_scenario.yaml` 白名单内；新维度需先扩展词库（doc/02 §11.4）。
3. 确认 `l3_baseline` 维度与 `config/keywords/l3_agent_persona.yaml` 一致。
4. `dla scenario validate <new_id>` 跑 schema 校验（复用 `dla keyword validate` 的 YAML 校验器）。
5. 本地 `dla chat --scenario <new_id> --explain` 跑一轮，确认 L3 人格符合预期；可选提交 `coupling_seeds` 走 `dla keyword review --rules`。
6. 若打算开源共享，`dla scenario export` 导出模板，提 PR 合入上游。
