# 05 · 实施路线与验收

## 1. 里程碑总览

按**可独立验证**的原则切分。每个里程碑结束都能跑起来看效果，不出现"写了三天还不能运行"的情况。

| 里程碑 | 内容 | 依赖 | 可验证产物 |
|---|---|---|---|
| **M0** | 项目骨架、配置、存储、迁移 | — | `dla init` 成功建库 |
| **M1** | 词库 + 权重引擎（纯函数，不联网） | M0 | 单测全绿，`dla keyword list` 有输出 |
| **M2** | 分析器 + Prompt 组装 + 编排引擎 | M1 | `dla bench` 跑通剧本 |
| **M2.3** | 工具插件框架与路由（doc/08） | M2 | `dla tool list` 有输出；路由召回候选正确 |
| **M2.5** | 向量化词库与在线学习（doc/06） | M2 | 冷启动生成身份关键字；跑通一步梯度更新，loss 下降 |
| **M2.6** | 情绪/脾性涌现式关键词与 kw_agent_map 推导（doc/02 §11.9） | M2 | LLM 提炼 `user_mood.*`/`user_temper.*` 累积；查表推导 L3 生效；映射随对话累积更新 |
| **M2.7** | 对话历史冷热记忆（doc/07, LangGraph+RAG） | M2.5, M2.6 | 多会话后能召回上一次关键事实；checkpoint 可 resume |
| **M3** | CLI 完整闭环（含 `--explain`） | M2.7 | 终端里完成真实对话 |
| **M4** | PyQt 界面 | M3 | 桌面窗口可对话、权重可见 |
| **M5** | FastAPI（可选） | M3 | curl 冒烟通过 |
| **M6** | 可观测性与调参 | M4 | `portrait history` 出曲线 |

**建议顺序**：M0 → M1 → M2 → M2.3 → M2.5 → M2.6 → M2.7 → M3 → M4。M5/M6 视精力与需求决定。

**强烈建议 M1 单独做完并评审**。因为权重引擎是纯函数、不依赖 LLM，这一阶段可以用最快的速度把整个项目的核心逻辑验证到位。如果权重模型的手感和预期不符，在 M1 修改的成本是 M3 之后的十分之一。

## 3. 测试策略

### 3.1 分层

| 层 | 范围 | 用什么 | 目标 |
|---|---|---|---|
| 单测 | 权重引擎、渲染器、预算裁剪、规则引擎、触发策略 | `pytest` + 假 LLM | 覆盖率 ≥ 85%（权重引擎） |
| 集成 | 真实 SQLite + 假 LLM 的完整一轮 | `pytest` + tmp 数据库文件 | 关键路径全通 |
| 剧本回归 | 多轮权重演化方向 | `dla bench` | 覆盖 3 类典型剧本 |
| 手动冒烟 | 真实 LLM 对话 | `dla chat` / Qt 界面 | 见各里程碑验收 |

### 3.2 关于 mock 的纪律

- **单测 mock 掉 LLMClient 与 Clock**，保持快速确定。
- **集成测试用真实 SQLite 文件**（临时目录），**不要 mock 仓储层**——仓储层与 SQL 的交互正是容易出错的地方，mock 掉就测不到了。
- **绝不在集成测试里 mock 服务层**，否则等于什么都没测。

### 3.3 权重引擎必须覆盖的用例

- 证据强度为 0 → conf = 0，权重 = 0
- 预设项反推：conf=0.9 / K=2 → E_preset = 18
- 半衰期衰减：经过 n 个半衰期，E 变为 1/2ⁿ
- 饱和累加：重复命中同一关键词，E 趋近 E_max 但不越过
- 类别型维度：softmax 后 argmax 唯一胜出
- 程度型维度：两个反向关键词加权平均得到中间值
- 规则 gate：条件置信度刚好在阈值附近时，增益是部分而非全量
- 预算裁剪：关键词数量超预算时，低权重词被裁掉且高权重词保留
- 滞回：Δ < τ_rebuild 时 Prompt 不重建
- 冷却：冷却期内的重建请求被拒绝且被记录

```
[ ] 删除必填环境变量后，启动报错可读且明确指向缺失项
[ ] 断网情况下，对话以友好错误结束，不抛未捕获异常
[ ] SQLite 外键约束已开启（PRAGMA foreign_keys=ON）
[ ] 所有表变更都有对应 migration 文件
```

## 5. 风险登记

| # | 风险 | 概率 | 影响 | 应对 |
|---|---|---|---|---|
| R1 | LLM 抽取关键词不稳定，同类表述给不同词 | 高 | 中 | 白名单词表 + 同义词归一 + 半衰期平滑；定期用丢弃日志反哺词库 |
| R2 | 耦合规则越写越多，互相打架难以维护 | 中 | 高 | 规则带 `id` 与 `note`，强制注释；规则数超 30 条时引入优先级分组与冲突检测工具 |
| R3 | 权重调参陷入无止境的手感调试 | 高 | 中 | 先跑 M1 单校准方向，再用 `dla bench` + 真实快照做数据驱动调参；参数全部可配 |
| R4 | Qt 线程处理不当导致随机崩溃 | 中 | 高 | 严守"worker 只发信号、主线程只更新 UI"；worker 必带异常兜底；关闭流程走优雅停止 |
| R5 | Prompt 过长导致成本失控 | 中 | 中 | 分层预算硬裁剪 + 每轮记录 token 数 + 设置上限告警 |
| R6 | PyQt 许可证合规问题 | 低 | 高 | `qt_compat` 抽象层；闭源分发前切 PySide6 |
| R7 | 词库设计不合理，维度划分混乱 | 中 | 中 | 首期只做 2~3 个场景、每层 10~20 词；`dla keyword validate` 强制 schema 校验 |

## 7. 后续可扩展方向（本期不做）

- **多用户与云端同步**：`sessions.user_id` 已预留，加认证层即可。
- **跨会话长期记忆**：把 `session_keyword_state` 聚合为 `user_keyword_state`，让 Agent 记得上次聊过什么。这是自然的下一步，架构已支持。
- **词库自动发现**：用被丢弃的"词表外关键词"做聚类，半自动生成新词候选，人工审核入库。
- **A/B 人格对比**：同一会话跑两套权重参数，对比效果。快照表为此提供了数据基础。
- **RAG 补充**：关键词是显式记忆，RAG 是语义记忆，两者互补而非替代——此能力已由 [07 · 对话历史冷热记忆](./07-对话历史冷热记忆(LangGraph+RAG).md)（LangGraph + 本地向量库）实现，并以冷热分层 + checkpoint 落地。

4. **调试模式展示完整思维链** → [04 §2.3](./04-交互层设计.md)（`--debug` + `--show-prompt`）+ §4.4（Qt 思维链面板）。

5. **词库向量化 + 在线学习 + 双反馈回路**（本次新增，评审中详述）→ [06 · 向量化词库与在线学习](./06-向量化词库与在线学习.md) + [02 §5.2/§11.8](./02-三层关键词权重模型.md) + [01 §1.2/D16–D18](./01-架构设计总览.md) + [03 §2.10–§2.14](./03-数据模型与存储.md)。要点：
   - 关键词编码为 d 维向量，跨层关联由可训练双线性矩阵 `M_r`（多关系头）表示；
   - 对话中 LLM 实时 `add/update/delete` 当前场景用户/Agent 关键词（带护栏）；
   - `M_r` 按学习率 + 损失函数（软交叉熵 + 排序边界 + 权重衰减）用解析梯度更新，纯 numpy、离线、不微调 LLM；
   - **双反馈回路**：前向（用户肖像丰富 → Agent 关键词贴合）+ 后向（满意度 → 反向调整 Agent 权重）收敛到用户理想对话方式。

6. **双运行模式 + 开场称呼生成**（本次新增）→ [01 §6 D19–D20 / §7 / §8](./01-架构设计总览.md) + [02 §3.5 / §12](./02-三层关键词权重模型.md) + [06 §4.4](./06-向量化词库与在线学习.md) + [04 §2 / §4.1 / §4.5](./04-交互层设计.md)。要点：
   - **固定场景模式**：用户显式指定场景模板，L1 关键词全程固定，可复现、适合教学/回归测试；
   - **自动场景模式**：无预设，对话中 LLM 经 `scene_ops` 实时判定并增删改 L1 场景关键词（带护栏，场景稳定后锁定）；
   - **开场称呼据 L1 场景权重由模型生成**；冷启动（auto 模式尚无 L1）回退 `你好/hi` 兜底；场景确立后可重新生成一次。

7. **对话历史冷热记忆以 LangGraph 单独实现**（本次新增）→ [07 · 对话历史冷热记忆](./07-对话历史冷热记忆(LangGraph+RAG).md) + [01 §1.2/D21/§4/§7/§8/§10](./01-架构设计总览.md)。要点：
   - **热记忆**=当前会话滑动窗口 + 活跃关键词状态（LangGraph in-graph state，零检索）；
   - **冷记忆**=历史轮次 / 抽取事实（本地向量库 top-K 语义检索，按需注入）；
   - LangGraph `StateGraph` 编排 `retrieve → prepare → generate → store → compact`，`SqliteSaver` checkpoint 到同一 SQLite；

8. **对话历史以"压缩摘要链"为默认载体、详情按需拉取**（本次新增）→ [01 §7/D22/§8](./01-架构设计总览.md) + [07 §4.6/§4.7](./07-对话历史冷热记忆(LangGraph+RAG).md) + [06 §4](./06-向量化词库与在线学习.md)。要点：
   - LLM 每轮回复必须在 schema 回传 `turn_summary`（≤100 字），作为下一轮默认历史上下文；
   - 完整对话原文**不进默认 Prompt**，仅存于冷热记忆；下一轮注入的历史 = 历轮 `turn_summary` 拼接；
   - 需回溯细节时由本地 `recall_memory` 工具按需取回原文片段，临时注入当前轮、不污染长期权重与摘要链。
   - 冷记忆**只作 Prompt 注入、不参与权重**，与 doc/06 的"词库向量化"是**两个独立向量空间**。

9. **自由模式（free）：无预设场景模板，但用户首轮提供自然语言"场景描述"，LLM 据此 Bootstrap 生成 L1/L2/L3 三层基础关键词作为起点，后续经 `scene_ops` / 用户肖像分析 / `agent_ops` / 在线学习逐步更新**（本次新增）→ [01 §6 D26 / §7 / §8](./01-架构设计总览.md) + [02 §3.5/§3.6/§12](./02-三层关键词权重模型.md) + [06 §3.1](./06-向量化词库与在线学习.md) + [04 §2/§4.1/§4.5](./04-交互层设计.md)。要点：
   - 与 **fixed**（模板固定）、**auto**（无预设、L1 从空由 `scene_ops` 建）并列的**第三种模式**；free 的 L1 从"描述 Bootstrapped"起步，既非空白也非冻结；
   - Bootstrap 三层关键词 `src_confidence=bootstrap(0.6)`（介于 `inferred 0.5` 与 `preset 0.8` 之间），L1 继承 auto 的 `scene_ops` 可调能力，L3 基础集作为 `w3_base` 一次性初始化（与 D3 不冲突：运行时 L3 仍只由推导+学习决定，Bootstrap 等同"加载一个隐式场景模板基线"）；
   - 后续对话中三层关键词经既有机制**逐渐更新**：L1 由 `scene_ops` 微调、L2 由用户肖像分析累积、L3 由耦合 + `agent_ops` + LVM 在线学习收敛到用户理想风格；
   - 因 L1 在开场前已播种，自由模式的开场称呼**直接场景感知、无需回退兜底**。

10. **中层情绪判定 + 用户肖像脾性关键词的涌现式更新（本次新增）→ [02 §11.9](./02-三层关键词权重模型.md) + [03 §2.15/§2.16](./03-数据模型与存储.md) + [05 M2.6](./05-实施路线与验收.md)。要点：**
   - 范围聚焦 `user_mood.*`（中层情绪判定：受挫/愤怒/平静/兴奋 + 强度标量）与 `user_temper.*`（用户肖像脾性：急躁/社恐/完美主义/幽默/冷淡等跨轮沉淀气质）；
   - **不可固定、不可由用户对话直接指定**：模板 YAML 不得 preset 情绪/脾性词（doc/09 硬约束），用户自陈"我脾气暴躁"不采信为关键词，二者均只经 LLM 对真实对话言行的提炼累积涌现；
   - LLM 提炼时一并给出"该词 → 目标 Agent 特质 + 方向 + 建议 delta"的映射建议，本地落 `kw_agent_map` 表并**按学习率 + 损失函数累积更新**；
   - 推导 Agent 关键词时本地**查表聚合**进 [02 §5.2](./02-三层关键词权重模型.md) 融合（δ 默认 0.15，Δmax 默认 0.30 防突变），与 M2.5 的 LVM 双线性矩阵**互补叠加**（主轴用可解释查表、其余用稠密 LVM）。

**仍建议动工前明确的一点**：首个落地场景（默认"语言学习/口语练习"）。它决定初始词库与耦合规则的形态，但不阻塞 M0–M1 的架构与权重引擎开发。
