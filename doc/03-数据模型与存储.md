# 03 · 数据模型与存储

## 1. 设计取向

SQLite + 标准库 `sqlite3`（决策 D9）。理由：单机单用户场景，schema 简单，引入 ORM 的收益不足以抵消依赖与学习成本。但**所有数据访问必须走 Repository 接口**，核心引擎只依赖协议，未来换 PostgreSQL 只需新增一个实现类。

两条硬规则：

1. **Schema 变更一律走 migration 文件**，禁止直接改已有的建表语句。每个迁移含 up 与 down，可回滚。
2. **连接必须显式管理事务**，多步写入用 `with conn:` 包裹；开启 `PRAGMA foreign_keys = ON`（SQLite 默认关闭外键，必须手动开）与 `PRAGMA journal_mode = WAL`（提升并发读写表现）。

## 2. 表结构

### 2.1 迁移版本表

```sql
CREATE TABLE schema_version (
    version    INTEGER NOT NULL,
    applied_at TEXT    NOT NULL DEFAULT (datetime('now'))
);
```

### 2.2 会话

```sql
CREATE TABLE sessions (
    id            TEXT PRIMARY KEY,             -- uuid4
    user_id       TEXT,                          -- 预留，首期恒为 NULL
    scenario_id   TEXT NOT NULL,                 -- 关联 config/scenarios/*.yaml
    title         TEXT,
    status        TEXT NOT NULL DEFAULT 'active',-- active | archived
    turn_count    INTEGER NOT NULL DEFAULT 0,
    created_at    TEXT NOT NULL,
    updated_at    TEXT NOT NULL
);
CREATE INDEX idx_sessions_updated ON sessions(updated_at DESC);
```

### 2.3 消息

```sql
CREATE TABLE messages (
    id              INTEGER PRIMARY KEY AUTOINCREMENT,
    session_id      TEXT NOT NULL REFERENCES sessions(id) ON DELETE CASCADE,
    turn            INTEGER NOT NULL,
    role            TEXT NOT NULL,               -- user | agent | system
    content         TEXT NOT NULL,
    prompt_snapshot TEXT,                        -- 本轮实际使用的 Prompt（JSON）
    prompt_tokens   INTEGER,
    completion_tokens INTEGER,
    latency_ms      INTEGER,
    model           TEXT,
    created_at      TEXT NOT NULL
);
CREATE INDEX idx_messages_session_turn ON messages(session_id, turn);
```

> **注意**：`content` 默认不写入日志；是否落库受 `DLA_STORAGE__SAVE_CONTENT` 控制（默认 true）。若涉及隐私场景可关闭，仅保留权重快照——因为没有正文也能复现人格演化轨迹。

### 2.4 关键词词典

```sql
CREATE TABLE keywords (
    id             TEXT PRIMARY KEY,             -- 'user_mood.frustrated'
    layer          TEXT NOT NULL,                -- L1 | L2 | L3
    dimension      TEXT NOT NULL,
    label          TEXT NOT NULL,
    kind           TEXT NOT NULL,                -- categorical | scalar
    description    TEXT NOT NULL DEFAULT '',
    base_weight    REAL NOT NULL DEFAULT 0.5,
    salience       REAL NOT NULL DEFAULT 1.0,
    half_life_hours REAL,                        -- NULL = 不衰减
    default_value  REAL,                         -- 仅 scalar
    aliases        TEXT,                         -- JSON 数组
    render_template TEXT,
    enabled        INTEGER NOT NULL DEFAULT 1,
    source_file    TEXT,                         -- 来源 YAML，便于追踪
    updated_at     TEXT NOT NULL
);
CREATE INDEX idx_keywords_layer ON keywords(layer, dimension);
```

词典实际以 YAML 为**唯一真源**，数据库表是它的**加载镜像**。启动时对比哈希，不一致则同步。这样既能版本化管理 YAML，又能用 SQL 做关联查询。

### 2.5 会话级关键词状态（热数据）

```sql
CREATE TABLE session_keyword_state (
    session_id     TEXT NOT NULL REFERENCES sessions(id) ON DELETE CASCADE,
    keyword_id     TEXT NOT NULL REFERENCES keywords(id),
    evidence       REAL    NOT NULL DEFAULT 0,   -- 衰减后的 E_t
    confidence     REAL    NOT NULL DEFAULT 0,   -- conf
    weight         REAL    NOT NULL DEFAULT 0,   -- w
    value          REAL,                          -- scalar 类型的当前值
    evidence_count INTEGER NOT NULL DEFAULT 0,
    first_seen_at  TEXT,
    last_seen_at   TEXT,
    updated_at     TEXT NOT NULL,
    PRIMARY KEY (session_id, keyword_id)
);
```

这是**当前状态的物化视图**，每次更新权重时重算，读取时无需回溯全部证据。证据流水另表保存，用于审计与重放。

### 2.6 证据流水（可回放）

```sql
CREATE TABLE keyword_evidence (
    id         INTEGER PRIMARY KEY AUTOINCREMENT,
    session_id TEXT NOT NULL,
    keyword_id TEXT NOT NULL,
    turn       INTEGER NOT NULL,
    intensity  REAL NOT NULL,                    -- [0,1]
    source     TEXT NOT NULL,                    -- preset | heuristic | llm
    reason     TEXT,                             -- 人类可读的理由
    raw        TEXT,                             -- LLM 原始输出，便于复盘
    created_at TEXT NOT NULL
);
CREATE INDEX idx_evidence_session_kw ON keyword_evidence(session_id, keyword_id);
CREATE INDEX idx_evidence_session_turn ON keyword_evidence(session_id, turn);
```

**为什么要存流水而不只存状态**：权重引擎的参数（K、半衰期）很可能需要反复调优。有了证据流水，改一个参数后可以**完全重算历史权重**，不必重新跑一遍对话。这对调参效率是决定性的。

### 2.7 权重快照（可观测性核心，决策 D10）

```sql
CREATE TABLE weight_snapshots (
    id         INTEGER PRIMARY KEY AUTOINCREMENT,
    session_id TEXT NOT NULL,
    turn       INTEGER NOT NULL,
    layer      TEXT NOT NULL,                    -- L1 | L2 | L3
    payload    TEXT NOT NULL,                    -- JSON 数组
    created_at TEXT NOT NULL
);
CREATE INDEX idx_snapshot_session_turn ON weight_snapshots(session_id, turn);
```

`payload` 结构：

```json
[
  { "keyword_id": "empathy", "weight": 0.78, "value": 0.78,
    "confidence": null, "evidence": null,
    "contributors": [
      { "rule": "boost_empathy_on_frustration", "gain": 0.35, "gate": 0.86 }
    ]
  }
]
```

`contributors` 字段记录每个增益来自哪条规则、gate 多少——**这就是"为什么"的答案**，直接支撑 UI 的可解释面板。

### 2.8 人格变更审计

```sql
CREATE TABLE persona_changes (
    id         INTEGER PRIMARY KEY AUTOINCREMENT,
    session_id TEXT NOT NULL,
    turn       INTEGER NOT NULL,
    delta      REAL NOT NULL,                    -- Δ
    action     TEXT NOT NULL,                    -- skipped | rebuilt | rebuilt_notified
    cooldown_blocked INTEGER NOT NULL DEFAULT 0,
    diff       TEXT NOT NULL,                    -- JSON: 变化最大的前 N 个维度
    created_at TEXT NOT NULL
);
```

### 2.8 词库候选表（词库演化支持）

对应 [02 文档 §11](./02-三层关键词权重模型.md) 的演化机制，存放 LLM 发现的、尚未正式收编的新概念。

```sql
CREATE TABLE keyword_candidates (
    id               TEXT PRIMARY KEY,        -- 建议 id，如 'pending.社恐'
    suggested_dimension TEXT NOT NULL,        -- 建议归属维度
    kind             TEXT NOT NULL,           -- categorical | scalar
    label            TEXT NOT NULL,
    description      TEXT,                    -- 给 LLM / 审核者的判定说明（中文）
    render_template  TEXT,                    -- LLM 生成的渲染模板（需注入校验）
    base_weight      REAL,
    salience         REAL,
    half_life_hours  REAL,
    source_evidence  TEXT,                    -- 触发它的原始片段 JSON
    observed_count   INTEGER NOT NULL DEFAULT 0,
    llm_verdict      TEXT,                    -- adopt | review | reject
    llm_confidence   REAL,
    llm_reason       TEXT,
    auto_added       INTEGER NOT NULL DEFAULT 0,
    status           TEXT NOT NULL DEFAULT 'pending', -- pending|approved|rejected
    first_seen_turn  INTEGER,
    created_at       TEXT NOT NULL
);
CREATE INDEX idx_candidates_status ON keyword_candidates(status);
```

> 该表与 `keywords` 是**隔离**的：候选在 approve 前不进入权重计算路径，审核或自动收编时才写入 `keywords` 并可能触发快照重建。

### 2.9 思考题：证据流水是演化的基石

[02 文档 §11.5](./02-三层关键词权重模型.md) 提到的 `rollback` 与"全量重算"，都依赖 [§2.6](./03-数据模型与存储.md) 的 `keyword_evidence` 流水。这也是为什么本项目从第一天起就坚持"存流水而非只存状态"——没有流水，词库演化就是空中楼阁。

### 2.10 关键词向量（向量化词库，doc/06）

对应 [06 · 向量化词库与在线学习](./06-向量化词库与在线学习.md) 的基础向量 `e_k`（**冻结不训练**）。

```sql
CREATE TABLE keyword_embeddings (
    keyword_id  TEXT PRIMARY KEY REFERENCES keywords(id) ON DELETE CASCADE,
    dim         INTEGER NOT NULL,
    vector      TEXT NOT NULL,       -- JSON 数组，d 个 float
    source      TEXT NOT NULL,       -- 'backbone' | 'random'
    updated_at  TEXT NOT NULL
);
```

### 2.11 关联矩阵（可训练"本地模型权重"）

每个关系头 `r` 一个双线性矩阵 `M_r ∈ R^{d×d}`（即 doc/06 中随损失函数更新的"本地模型权重"）。

```sql
CREATE TABLE lvm_relation_heads (
    head        TEXT PRIMARY KEY,    -- 'scene_agent'|'user_agent'|'user_user'|'scene_constraint'
    dim         INTEGER NOT NULL,
    matrix      TEXT NOT NULL,       -- JSON 二维数组 d×d
    bias        TEXT,                -- JSON 数组，每词偏置（可空）
    updated_at  TEXT NOT NULL
);
```

### 2.12 词库操作日志（LLM 实时增删改）

记录每轮分析产出的 `agent_ops` / 用户侧增删改，可审计、可回放。

```sql
CREATE TABLE lexicon_ops (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    session_id  TEXT NOT NULL,
    turn        INTEGER NOT NULL,
    op_type     TEXT NOT NULL,       -- add | update | delete
    layer       TEXT NOT NULL,       -- L2 | L3
    target_key  TEXT,                -- 操作目标关键词（add 时可为空，由 LLM 建议）
    payload     TEXT,                -- JSON：delta / label / dimension / render_template / conf
    llm_reason  TEXT,
    applied     INTEGER NOT NULL DEFAULT 0,
    created_at  TEXT NOT NULL
);
CREATE INDEX idx_lexicon_ops_session ON lexicon_ops(session_id, turn);
```

> 与 `keyword_candidates` 的区别：候选表管"新概念是否收编进主词表"；`lexicon_ops` 管"运行期对当前场景工作集的即时增删改操作"，二者都落库，但职责不同。

### 2.13 满意度反馈信号（后向回路监督源）


### 2.14 LVM 检查点与训练日志

```sql
CREATE TABLE lvm_training_log (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    session_id  TEXT NOT NULL,
    turn        INTEGER NOT NULL,

    lr          REAL,
```

## 3. Repository 接口

核心引擎只依赖下面这组协议（`core/ports.py`），不认识 SQL：

```python
class SessionRepository(Protocol):
    def create(self, session: Session) -> None: ...
    def get(self, session_id: str) -> Session | None: ...
    def list_recent(self, limit: int = 20) -> list[Session]: ...
    def bump_turn(self, session_id: str, turn: int) -> None: ...

class MessageRepository(Protocol):
    def append(self, message: Message) -> int: ...
    def list_by_session(self, session_id: str) -> list[Message]: ...
    def recent(self, session_id: str, n: int) -> list[Message]: ...

class KeywordStateRepository(Protocol):
    def load_session(self, session_id: str) -> dict[str, KeywordState]: ...
    def upsert_many(self, session_id: str, states: Iterable[KeywordState]) -> None: ...
    def soft_reset(self, session_id: str, layer: Layer) -> None: ...

class EvidenceRepository(Protocol):
    def add_many(self, evidences: Iterable[Evidence]) -> None: ...
    def list_for_recompute(self, session_id: str) -> list[Evidence]: ...

class SnapshotRepository(Protocol):
    def save_layer(self, session_id: str, turn: int,
                   layer: Layer, payload: list[dict]) -> None: ...
    def history(self, session_id: str, layer: Layer) -> list[Snapshot]: ...

class CandidateRepository(Protocol):
    def add(self, candidate: KeywordCandidate) -> None: ...
    def bump_observation(self, candidate_id: str, evidence: str, turn: int) -> None: ...
    def pending(self) -> list[KeywordCandidate]: ...
    def resolve(self, candidate_id: str, status: str) -> None: ...
    def promote(self, candidate_id: str, as_keyword: Keyword) -> None: ...
    def rollback_auto_added(self, keyword_id: str) -> None: ...

class EmbeddingRepository(Protocol):
    def get(self, keyword_id: str) -> list[float] | None: ...
    def upsert_many(self, rows: Iterable[tuple[str, int, list[float], str]]) -> None: ...

class LvmHeadRepository(Protocol):
    def load_all(self) -> dict[str, tuple[list[list[float]], list[float] | None]]: ...
    def save_head(self, head: str, matrix: list[list[float]], bias: list[float] | None) -> None: ...
    def load_state(self) -> dict[str, object]: ...
    def save_state(self, state: dict[str, object]) -> None: ...

class LexiconOpRepository(Protocol):
    def add(self, op: LexiconOp) -> None: ...
    def recent(self, session_id: str, n: int) -> list[LexiconOp]: ...

class FeedbackRepository(Protocol):
    def add(self, fb: FeedbackSignal) -> None: ...
    def for_session(self, session_id: str) -> list[FeedbackSignal]: ...

class LvmLogRepository(Protocol):
    def append(self, entry: LvmLogEntry) -> None: ...
```

## 4. 迁移机制

自建轻量 migration runner，不引入 Alembic。

```
migrations/
├── 001_init.sql
├── 002_add_persona_changes.sql
└── 003_xxx.down.sql          # 可选，回滚脚本
```

约定：
- 每个迁移文件在**事务内**执行，失败自动回滚。
- 执行成功后写入 `schema_version`。
- `DLA_DB__AUTO_MIGRATE=true` 时启动时自动执行；生产建议设 false，手动执行 `dla db upgrade`。
- 提供 `dla db current` / `upgrade` / `downgrade --to N`。

首期迁移数量少，但这套机制从第一天就位——**等到需要时再加迁移，代价要高得多**。

## 5. 关键查询与性能

| 场景 | 查询 | 索引支撑 |
|---|---|---|
| 加载会话当前权重 | `SELECT * FROM session_keyword_state WHERE session_id=?` | 主键 |
| 重算历史权重 | `SELECT * FROM keyword_evidence WHERE session_id=? ORDER BY turn` | `idx_evidence_session_turn` |
| 渲染权重演化曲线 | `SELECT turn, payload FROM weight_snapshots WHERE session_id=? AND layer=?` | `idx_snapshot_session_turn` |
| 加载最近上下文 | `SELECT role, content FROM messages WHERE session_id=? ORDER BY turn DESC LIMIT ?` | `idx_messages_session_turn` |

数据量预期：单会话数百条消息、数千条证据，全表扫描也无压力。索引主要是为了**演进曲线面板的实时渲染**。

## 6. 写入策略

一轮对话的所有落库操作放在**同一个事务**里：

```python
with db.transaction() as conn:
    msg_repo.append(user_message)
    state_repo.upsert_many(updated_states)
    evidence_repo.add_many(new_evidences)
    snap_repo.save_layer(...)          # L1 / L2 / L3 三次
    audit_repo.record(persona_change)
    session_repo.bump_turn(...)
```

**但流式生成期间不能持有事务**——生成可能持续数十秒。策略：

1. 用户消息 + 证据 + 权重快照：**生成前**提交一次（事务 A）。
2. Agent 回复 + 最终 token 统计：**生成完成后**提交一次（事务 B）。

这样长事务被拆开，UI 也不会被 SQLite 写锁阻塞。

## 7. 备份与导出

```bash
dla session export <id> --format json   # 完整会话（消息+证据+快照）
dla session export <id> --format md     # 人类可读的对话记录 + 权重演化摘要
dla db vacuum                            # 回收空间
```

导出格式为后续做离线分析与调参提供数据源。
