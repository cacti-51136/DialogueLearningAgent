# 02 · 三层关键词权重模型（核心）

> 这一篇是整个项目的技术核心。前两层是"输入"，第三层是"输出"，中间由**耦合规则**连接。
> 所有公式都设计为**纯函数**，不碰网络、不碰数据库，因此可以脱离大模型做完整的单元测试。

## 1. 设计哲学

在动手看公式前，先明确三条原则，它们决定了下面每一个细节的形状：

1. **可解释优先于玄学。** 每一个权重变化都要能回答"为什么"。所以我们保留证据流水、保留快照、保留变更审计，宁可多存几张表，也不做无法追溯的黑箱打分。
2. **稳定优先于灵敏。** 人格频繁跳变比反应迟钝更伤体验。所以有半衰期、有滞回阈值、有冷却轮次——**变化必须是渐进的**。
3. **确定优先于智能。** 能用规则算清楚的绝不问模型。LLM 只用于规则覆盖不到的长尾抽取与精炼，且它的意见只占可配的一小部分（β）。

## 2. 关键词的统一数据结构

三层共用同一个模型，靠 `layer` 字段区分。

```python
@dataclass(frozen=True)
class Keyword:
    id: str                  # 'user_mood.frustrated'
    layer: Layer             # L1 | L2 | L3
    dimension: str           # 'user_mood' —— 维度，归一化与冲突的作用域
    label: str               # '情绪·受挫'，用于 UI 展示
    kind: KeywordKind        # CATEGORICAL | SCALAR
    description: str         # 给 LLM 看的判定说明
    base_weight: float       # 基础权重 w_base ∈ [0,1]
    salience: float          # 显著性系数，默认 1.0
    half_life_hours: float | None   # None = 不衰减（预设项）
    default_value: float | None     # 仅 SCALAR 使用
    aliases: tuple[str, ...]        # 同义词，用于归一
    render_template: str     # '- {label}：{value_text}'
    enabled: bool = True
```

### 2.1 类别型 vs 程度型（决策 D1）

这是避免人格自相矛盾的关键设计。

- **类别型（categorical）**：同一个 `dimension` 下互斥，只能选一个。
  例如 `agent_role` ∈ {`外教`, `同事`, `朋友`, `考官`}。按权重取 argmax 胜出。
- **程度型（scalar）**：连续值 ∈ [0,1]，同维度下多个关键词**加权平均**成一个数值。
  例如 `verbosity` 维度下有 `简洁` 与 `详尽` 两个关键词，权重分别 0.3 和 0.7，则最终 `verbosity = 0.7`（偏详尽）。

有了程度型，"简洁"和"详尽"不再是二选一的死斗，而是可以共存的张力——系统得出的是**一个平衡点**，这更接近真人交流的状态。

## 3. L1 · 功能场景层

### 3.1 定位

回答"**这是一场什么样的对话**"。它设定舞台，也划定 L3 人格的候选空间。

典型维度：

| 维度 | 说明 | 示例关键词 |
|---|---|---|
| `scene` | 对话场景（类别型） | 口语练习、电商客服、桌面宠物陪伴、虚拟恋人、模拟面试（内置预设见 [09-预设场景与角色模板库](./09-预设场景与角色模板库.md)，对应 `scene.oral_practice` / `scene.customer_service` / `scene.companion` / `scene.romantic_companion` / `scene.interview_sim`） |
| `goal_agent` | Agent 侧目标 | 引导开口、纠正语法、追问细节、安抚情绪 |
| `goal_user` | 用户侧目标 | 提升流利度、准备面试、解决报错 |
| `domain` | 话题领域 | 职场、旅行、学术、日常 |
| `constraint` | 约束条件 | 只说英文、不纠错、回复不超过 3 句 |
| `difficulty` | 难度（程度型） | 入门 / 进阶 / 高阶 |
| `formality` | 正式度（程度型） | 正式 / 随意 |

### 3.2 权重计算

L1 相对静态，权重主要取决于**来源可信度**：

```
w1(k) = w_base(k) × src_confidence(source) × salience(k)

src_confidence:
    user_explicit  = 1.00   # 用户显式选择（如命令行指定 --scenario）
    preset         = 0.80   # 场景模板预设
    bootstrap      = 0.60   # 自由模式 LLM 由描述 Bootstrap 生成（见 §3.6）
    inferred       = 0.50   # 系统推断（auto 模式 scene_ops 实时判定）
```

### 3.3 层内归一化

按 `dimension` 分组：

- 类别型维度：**softmax 归一化后取 argmax**（温度参数 τ_softmax 默认 0.5，可调尖锐度），其余同维度词降权到 0。
- 程度型维度：**加权平均**成一个标量值。

```python
def resolve_l1(keywords, state) -> dict[str, KeywordValue]:
    # 按维度分组后分别处理，输出 {dimension: KeywordValue}
```

### 3.4 场景层的特殊能力：硬约束

`constraint` 维度下的关键词具有**否决权**，不参与权重竞争，直接作为不可违背的规则注入 Prompt 末尾。例如"只说英文"即使权重不高也必须生效。

这是刻意的例外——**有些东西不该由权重投票决定**。

### 3.5 场景来源模式：固定 vs 自动（决策 D19）

L1 场景关键词**从哪来、会不会被自动改**，由运行模式决定。这是 [01 §6 D19](./01-架构设计总览.md) 提出的双运行模式在权重层的落点。

| 模式 | 场景来源 | L1 是否自动变更 | 适用 |
|---|---|---|---|
| **固定场景模式（fixed）** | 用户显式指定/选择的场景模板（CLI `--scenario`、界面下拉） | 否，全程固定 | 已知场景、教学/演示、需可复现的回归测试 |
| **自动场景模式（auto）** | 无预设；对话中由 LLM 依据内容判定并更新 | 是，通过 `scene_ops` 实时增删改（带护栏） | 零配置上手、未知/混合场景、开放闲聊 |
| **自由模式（free）** | 无预设模板；用户开场提供自然语言"场景描述"，LLM **Bootstrap** 一次性生成 L1/L2/L3 三层基础关键词作起点（见 §3.6） | 是，继承 auto 的 `scene_ops` 能力继续微调（带护栏） | 想要"有引导的开放"：起点确定（称呼可场景化、人格不空白）且可演化 |

**三种模式下 L1 权重的计算路径完全一致**（§3.2 的 `src_confidence` 与 §3.3 归一化不受影响），区别只在于"谁提供了这些词、以及后续能不能改"：

- 固定模式：`source = user_explicit(1.00)` 或 `preset(0.80)`，权重稳定，人格可复现。
- 自动模式：冷启动阶段 L1 为空；随着 `scene_ops` 累积，词的 `source` 从 `inferred(0.50)` 起步，置信度随观测次数上升（与 L2 观察项同一套证据模型，见 §4.2）。**场景一旦被 LLM 判定稳定，即视为该会话的临时"预设"，后续不再随意漂移**——通过给 `scene_ops` 产出的词设置较高 `E_preset` 等效初始证据，避免场景在前几轮反复横跳。

> 自动模式的代价是**前几轮 L1 不确定**：此时 Agent 人格缺乏场景锚点。这正是 §12 开场称呼需要"无权重时回退兜底"的原因——也是为什么固定模式在可复现性上仍不可替代。

### 3.6 自由模式冷启动：由描述引导 LLM 生成三层基础关键词（决策 D26）

自动模式（auto）的冷启动是"从空白 L1 起步，靠对话中 `scene_ops` 慢慢建"（见 §3.5）。这带来前几轮 L1 不确定、开场称呼只能回退兜底的问题。自由模式（free）补上另一种冷启动：**用户在开场前提供一段自然语言"场景描述"，LLM 据此一次性生成三层的基础关键词集**，作为对话起点，之后再由既有机制逐步更新（即用户要求的"再逐渐更新"）。

**触发**：仅 `free` 模式、且会话首轮尚未有 L1 时。描述来源：CLI `--describe "..."`、界面首屏文本框、或交互式追问。若 `DLA_MODE__FREE_REQUIRE_DESC=true` 且缺描述，则降级为 auto 模式并告警。

**Bootstrap 调用（一次性的结构化输出，独立于每轮分析）**：

```
system: 你是关键词引导器。根据用户给出的"对话场景描述"，为三层各产出一组基础关键词。
        每层只输出受控词表内的词（白名单校验），附强度 0~1。
user:   <场景描述文本>
→ 结构化输出：
{
  "l1": [ {"key":"scene.oral_practice","intensity":0.9},
          {"key":"goal_agent.elicit_speech","intensity":0.7},
          {"key":"domain.career","intensity":0.6},
          {"key":"constraint.english_only","intensity":0.5} ],
  "l2": [ {"key":"user_level.intermediate","intensity":0.7},
          {"key":"user_profile.working_pro","intensity":0.6},
          {"key":"user_goal.fluent","intensity":0.8} ],
  "l3": [ {"key":"agent_role.patient_tutor","intensity":0.8},
          {"key":"agent_tone.gentle","intensity":0.7},
          {"key":"empathy","value":0.8},
          {"key":"correction_mode.delayed","intensity":0.6} ]
}
```

**落地规则（与既有权重路径完全兼容）**：

- **L1 播种**：每个词的 `source = bootstrap`，`src_confidence = 0.60`（见 §3.2，介于 `inferred 0.5` 与 `preset 0.8` 之间——比实时推断可靠，比策展模板保守）。这些词**带 `bootstrap` 标记**，后续可被 `scene_ops` 调整或删除，避免一次性判定固化。
- **L2 播种**：作为**预设项**注入（走 §4.2 的 D2 反推公式，按 `conf≈0.7` 给 `E_preset ≈ 4.67`），与用户后续观察项共用同一证据模型累加。
- **L3 播种**：作为 **`w3_base` 基线种子**一次性写入（对应 §5.2 阶段一的 `scenario_baseline`）。**这与 D3 不冲突**——D3 约束的是"运行时 L3 不由每轮用户输入直接决定"；Bootstrap 等同"加载了一个隐式场景模板的基线"，此后 L3 仍只由耦合规则 + LLM 精炼 + LVM 先验 + 在线学习决定，Bootstrap 种子只提供初始锚点。
- 三层所有词都必须过**白名单校验**（不在词表内的丢弃 + 记日志，用于反哺词库）；L3 的 `add` 类若涉及新维度则走 [02 §11.4](./02-三层关键词权重模型.md) 审核，不自动收编。

**与 auto 模式的本质区别**：auto 是"边聊边建 L1"，free 是"开场先建好 L1/L2/L3 再聊"。free 保留了 auto 的**可演化性**（`scene_ops` 仍开启），又拿到了 fixed 的**确定性起点**（L1 一开场就就绪，称呼可场景化、LVM 身份生成直接场景化）。它是"有引导的开放模式"。

**后续逐步更新**（即用户要求的"再逐渐更新"）：

| 层 | 启动后如何逐步更新 |
|---|---|
| L1 | `scene_ops` 在对话中继续微调/增删场景关键词（同 auto）；Bootstrap 词因带 `bootstrap` 标记而允许被改 |
| L2 | 用户肖像分析（§4）持续累积观察项证据，与 Bootstrap 预设项叠加演化 |
| L3 | 耦合规则 + `agent_ops` + LVM 在线学习（doc/06）使其从种子收敛到"该用户、该风格最满意"的定点 |

> 衔接：Bootstrap 产出的 L1/L2/L3 种子如何接入向量化与在线学习（LVM 身份生成即场景化、L3 种子作 `w3_base`、在线学习从种子起步），见 [06 §3.1](./06-向量化词库与在线学习.md)。

## 4. L2 · 用户肖像层

### 4.1 定位

回答"**对面是谁，他现在怎么样**"。这是三层中唯一随时间动态演化的层，也是本项目"学习"能力的载体。

- **预设项（preset）**：用户主动填写或配置注入，如职业、母语、学习目标。稳定，不衰减。
- **观察项（observed）**：对话中分析得出，如当前情绪、知识水平、偏好、卡点。有半衰期。

典型维度：

| 维度 | 类型 | 关键词示例 |
|---|---|---|
| `user_profile` | 类别型 | 学生、职场人、转行者 |
| `user_mood` | 类别型 | 兴奋、平静、困惑、受挫、疲惫 |
| `user_level` | 类别型 | 零基础、初级、中级、高级 |
| `user_pref_style` | 类别型 | 偏好示例、偏好规则、偏好追问 |
| `stuck_point` | 类别型（多值） | 时态混淆、发音、词汇量不足 |
| `engagement` | 程度型 | 投入度 0~1 |
| `patience` | 程度型 | 耐心程度 0~1 |

### 4.2 统一的证据—置信度模型（决策 D2）

**核心公式**：

```
给定关键词 k 在时刻 t 的证据集合 {(intensity_i, t_i)}：

  1) 时间衰减后的有效证据强度
     E_t(k) = Σ_i [ intensity_i × exp(-λ × Δt_i) ]  +  E_preset(k)
     其中 λ = ln(2) / half_life，Δt_i = t - t_i（小时）
     半衰期为 None（预设项）时该分量不衰减

  2) 置信度（贝叶斯平滑，K 为先验强度，默认 2.0）
     conf(k) = E_t(k) / (E_t(k) + K)

  3) 最终权重
     w2(k) = w_base(k) × conf(k) × salience(k)
```

**预设项如何并入同一公式**（D2 的精髓）：给定期望置信度 `c`，反推等效初始证据强度：

```
E_preset = K × c / (1 - c)
```

例如希望预设项以 0.9 的置信度起步、K=2，则 `E_preset = 2 × 0.9 / 0.1 = 18`。
这样**预设项和观察项走完全相同的代码路径**，只是预设项的 `half_life = None`（不衰减）且初始证据很高。未来要给预设项加衰减，也只是改一个参数。

### 4.3 证据强度的来源与合并

| 来源 | 说明 | 强度范围 |
|---|---|---|
| `preset` | 配置注入 | 由反推公式决定 |
| `heuristic` | 本地启发式（正则 / 词典 / 统计量） | 0.3 ~ 0.6（保守） |
| `llm` | LLM 结构化抽取 | 由模型给出，裁剪到 [0,1]，默认乘 0.8 折扣 |

**同一轮同一关键词多次命中如何合并？** 不是简单相加（会导致重复刷分），而是**取饱和式累加**：

```
E_new = E_old + intensity × (1 - E_old / E_max)
```

`E_max` 默认 20。含义是：证据越多，新增证据的边际贡献越小，天然形成上限，避免某个关键词在长对话中无限膨胀、一家独大。

### 4.4 完整演算示例

设 K=2.0，半衰期 6 小时，关键词 `user_mood.frustrated`，`w_base=0.8`，`salience=1.0`。

**第 1 轮**，用户说："这个时态我怎么都搞不懂，烦死了。"
LLM 抽取：`{key: user_mood.frustrated, intensity: 0.7}`

```
E = 0 + 0.7 × (1 - 0/20) = 0.7
conf = 0.7 / (0.7 + 2.0) = 0.259
w2   = 0.8 × 0.259 × 1.0 = 0.207
```
→ 单条证据不足以定论，权重温和上升。这是**刻意的保守**。

**第 3 轮**，用户又说："算了我不问了，太难了。"
再次命中：`intensity = 0.8`

```
E = 0.7 + 0.8 × (1 - 0.7/20) = 0.7 + 0.772 = 1.472
conf = 1.472 / (1.472 + 2.0) = 0.424
w2   = 0.8 × 0.424 = 0.339
```

**第 10 轮**，用户情绪好转，此后 12 小时（2 个半衰期）未再出现受挫信号：

```
E = 1.472 × exp(-ln2 × 12 / 6) = 1.472 × 0.25 = 0.368
conf = 0.368 / (0.368 + 2.0) = 0.155
w2   = 0.8 × 0.155 = 0.124
```

→ 旧印象自然淡去，无需人工重置。**这就是"学习"二字的实现方式：不是记住，而是带遗忘地更新。**

## 5. L3 · Agent 肖像层

### 5.1 定位

回答"**那么我此刻应该是什么样的交流对象**"。

**关键性质**：L3 不接受任何直接输入。它完全由 L1 与 L2 推导（决策 D3）。这保证了人格永远服务于场景与用户，而不是一套脱离上下文的固定人设。

典型维度：

| 维度 | 类型 | 关键词示例 |
|---|---|---|
| `agent_role` | 类别型 | 耐心外教、严格考官、同行同事、倾听朋友 |
| `agent_tone` | 类别型 | 温和、幽默、专业、直率 |
| `correction_mode` | 类别型 | 即时纠错、延时纠错、不纠错 |
| `empathy` | 程度型 | 共情度 0~1 |
| `verbosity` | 程度型 | 简洁 ←→ 详尽 |
| `proactivity` | 程度型 | 主动性 0~1（是否主动抛出话题） |
| `language_level` | 类别型 | A1 / A2 / B1 / B2 / C1 |

### 5.2 推导机制

#### 阶段一：基线（来自 L1）

每个 L3 关键词在每个场景下有一个基线值，来自场景模板：

```
w3_base(k) = scenario_baseline[k]        # 场景模板中定义，缺省 0
```

#### 阶段二：规则推导（确定性，主力）

耦合规则形如：

```yaml
# config/coupling_rules.yaml
- id: boost_empathy_on_frustration
  when:
    all:
      - layer: L2
        key: user_mood.frustrated
        conf_gte: 0.55
  then:
    - { key: empathy,          op: add,  value: 0.35 }
    - { key: correction_mode.strict, op: add, value: -0.30 }
    - { key: agent_tone.humorous,    op: add, value: 0.10 }
  weight: 1.0
  note: 用户受挫时提升共情、降低纠错严厉度

- id: lower_complexity_for_beginner
  when:
    any:
      - { layer: L2, key: user_level.beginner, conf_gte: 0.6 }
      - { layer: L2, key: stuck_point.tense_confusion, conf_gte: 0.7 }
  then:
    - { key: language_level, op: set_value, value: 0.25 }   # 对应 A2
    - { key: verbosity.concise, op: add, value: 0.20 }
  weight: 0.9
```

规则引擎输出：

```
w3_rule(k) = clamp( w3_base(k) + Σ_r [ gain_r(k) × weight_r × gate_r ], 0, 1 )
```

其中 `gate_r` 是该规则条件被满足的程度（0~1 连续值，而非布尔），做法：

```
gate_r = min( conf(k_cond) 映射到 [0,1] 的满足度 )
```

**用连续 gate 而非布尔开关**，是为了让规则触发也保持平滑——条件"刚好差一点"时给部分增益，而不是突然从 0 跳到 0.35。

#### 阶段三：LLM 精炼（可选，长尾补充）

把当轮 L1 + L2 的权重快照序列化成紧凑文本，交给一个**便宜的小模型**，要求它输出对 L3 的微调建议：

```json
{
  "adjustments": [
    { "key": "proactivity", "delta": 0.2, "reason": "用户连续两轮只答单词，需要更多引导" }
  ]
}
```

校验规则：key 必须在 L3 词表内、`delta ∈ [-0.5, 0.5]`、条数 ≤ 5。不合规整批丢弃，不影响主流程。

#### 阶段四：融合

```
w3(k) = clamp( (1 - β - γ) × w3_rule(k) + β × w3_llm(k) + γ × p_agent(k), 0, 1 )
```

- β 默认 **0.3**（LLM 精炼融合权重）；γ 默认 **0.2**（`DLA_LVM__L3_PRIOR_GAMMA`，来自本地向量化模型的学习先验，详见 [06 · 向量化词库与在线学习](./06-向量化词库与在线学习.md)）。
- `p_agent(k) = softmax_k( S_user_agent(q_t, e_k) / τ )`，即 LVM 对"当前上下文 q_t（场景 + 已积累用户肖像）"检索出的 Agent 关键词先验软分布。
- 若本轮未启用 LLM 精炼，则 `w3_llm(k) = 0`；若 LVM 未启用，则 `γ = 0`，退化为原有双源公式。
- 融合后 `w3` 仍进入 §7.4 的 Δ 滞回 + 冷却判定，**学习不会破坏稳定性**。

**分歧护栏**：若 `|w3_rule(k) - w3_llm(k)| > 0.5`，判定为严重分歧，**以规则为准**并记录 warn 日志。规则的确定性优先于模型的灵光一现。

### 5.3 层内归一化（同 L1）

- 类别型维度：softmax + argmax
- 程度型维度：加权平均

## 6. 层间耦合总图

```
        L1 场景（相对静态，权重高）
            │
            │  ① 提供 L3 基线值
            │  ② 划定 L3 候选空间（某场景下不可能出现的角色直接置 0）
            │  ③ 提供硬约束（constraint 维度，否决权）
            ▼
        ┌───────────────┐
        │  耦合规则引擎  │◀── L2 用户肖像（动态，带置信度）
        │  + LLM 精炼    │
        └───────┬───────┘
                │ 输出 L3
                ▼
        ┌───────────────┐
        │ 稳定性判定     │  滞回 + 冷却
        └───────┬───────┘
                ▼
        ┌───────────────┐
        │ Prompt 组装器  │  分层预算 + 渲染
        └───────┬───────┘
                ▼
          System Prompt
```

## 7. Prompt 组装

### 7.1 分层预算（决策 D5）

```
总预算（默认 900 tokens）
  ├─ L1 场景段    25%   → 225
  ├─ L2 用户适配  20%   → 180
  └─ L3 人格段    55%   → 495
```

每层内**按权重降序**取词，累加预估 token，超出该层预算即停止。这保证最重要的词一定进 Prompt，长尾词被自然裁掉。

### 7.2 段落顺序

顺序不是随意的，考虑的是**注意力分布**：

```
1. 固定骨架前缀      （"你是一个…"，来自场景模板）
2. 【场景】L1 段      —— 舞台设定
3. 【人格】L3 段      —— 你是什么样的人
4. 【用户】L2 段      —— 对面是谁（贴近输入，注意力更集中）
5. 【硬约束】constraint —— 不可违背的规则，放最后最醒目
6. 输出格式约束       （长度、语言、禁止项）
```

### 7.3 渲染

每个关键词按 `render_template` 渲染成一行短句，而不是丢一堆标签给模型。标签对模型的可读性远不如自然语句。

```
【场景】
- 这是一场英语口语练习，你的目标是引导用户多开口
- 用户的目标是提升表达流利度
- 话题领域：职场

【你的人格】
- 角色：一位耐心的外语老师
- 语气：温和且带一点幽默
- 共情程度：较高（0.78）
- 纠错方式：延时纠错，不在用户表达中途打断
- 语言难度：A2，使用简单句与高频词汇
- 回复长度：偏简洁，每次不超过 3 句

【关于对话对象】
- 用户当前情绪：有些受挫（置信度 0.62）
- 用户水平：初级，时态使用存在困难
- 用户偏好：更接受具体示例而非语法规则讲解

【硬性要求】
- 全程使用英文，除用户明确要求解释语法外

【输出约定】
- 每次回复控制在 3 句以内
- 先回应用户的情绪，再推进话题
```

### 7.4 稳定性机制（决策 D6）

这是防止"人设跳变"的核心。

**距离度量**：将 L3 的程度型维度组成向量，类别型维度按 one-hot 拼接，计算 L1 距离：

```
Δ = Σ_dims | v_new - v_old | / dim_count
```

**决策表**：

| 条件 | 动作 | 用户可见 |
|---|---|---|
| `Δ < τ_rebuild`（0.15） | **不重建**，沿用上一轮 Prompt | 无 |
| `τ_rebuild ≤ Δ < τ_notify`（0.40） | 重建 Prompt | 无（权重面板可见） |
| `Δ ≥ τ_notify` | 重建 + 主动说明调整 | 有，如"我放慢一点节奏，我们多练几句" |
| 距上次重建 < 冷却轮次（2） | 强制不重建 | 无 |

**为什么需要主动说明**：当人格发生明显切换时，如果不解释，用户会觉得"这 AI 怎么突然变了"；一句话的解释反而会强化"它在适应我"的感知，这是本项目的体验亮点。

## 8. 分析器触发策略（决策 D7）

不是每轮都调 LLM 分析。三重触发：

| 触发 | 条件 | 目的 |
|---|---|---|
| 冷启动 | 前 `COLD_START_TURNS`（2）轮强制分析 | 尽快建立初始用户肖像 |
| 周期 | 每 `PERIOD`（3）轮 | 稳定更新 |
| 事件 | 本地启发式命中：消息长度骤变 > 60%、负面情绪词典命中、连续 2 轮追问同一概念、显式反馈（"太难了"/"换个话题"） | 关键时刻不遗漏 |

**启发式永远是同步且免费的**，它先跑；只有启发式认为"值得深挖"或满足周期条件时，才调用 LLM 分析。这把 LLM 调用量压到原来的三分之一左右。

## 9. 可解释性：为什么这么回

每一轮都输出如下诊断信息，CLI 用 `--explain` 打印，Qt 界面在侧栏实时显示：

```
── 第 12 轮 · 权重诊断 ────────────────────────────

           goal_agent.elicit_speech   0.80  [preset]

           user_level.beginner        0.51  conf=0.64  E=3.55

─────────────────────────────────────────────────
```

## 10. 参数默认值的来源

下表的默认值都是**保守起点**，不是调优结论。真正的调参要等 `dla bench` 剧本回放与真实快照数据积累后做，届时这些值应写入配置而非硬编码。

| 参数 | 默认 | 调大的效果 | 调小的效果 |
|---|---|---|---|
| `K` 先验强度 | 2.0 | 更迟钝，需要更多证据才改变 | 更灵敏，一两条证据就调整 |
| `half_life` | 6h | 记忆更持久 | 更健忘，更快回归基线 |
| `E_max` | 20 | 允许更强的单一印象 | 印象上限更低，更易反转 |
| `β` LLM 融合 | 0.3 | 更依赖模型判断，更灵活 | 更依赖规则，更可预测 |
| `τ_rebuild` | 0.15 | 人格更稳定，反应更慢 | 人格更善变 |
| `τ_notify` | 0.40 | 更少主动说明 | 更频繁地解释自己的调整 |
| L3 预算占比 | 0.55 | 人格描述更详尽 | 人格更精简，留出更多上下文 |

## 11. 词库自动演化（Lexicon Evolution）

> 用户确认：**词库需要随对话不断自动更新，且"更新词 / 更新规则"这类判定场景要引入大模型逻辑。**
> 这意味着词表不再是设计期写死的静态资产，而是会在运行中生长。

### 11.1 为什么需要演化

封闭词表有两个死穴：

1. **用户语言不可枚举**。一个学口语的人可能冒出"社恐""内卷""躺平"，一个技术答疑场景会冒出项目特有的黑话。冻结词表意味着这些信号永远进不了权重。
2. **领域随时间漂移**。今天没有的词，三个月后可能成了高频词。

但**完全自动、无约束地长词**会立刻失控——维度爆炸、同义重复、render 模板乱写。所以演化必须**受控**：候选 → LLM 判定 → 分级采纳 → 人工审核兜底。

### 11.2 三类更新与对应的判定职责

| 更新类型 | 谁判定 | 是否自动进主词表 | 说明 |
|---|---|---|---|
| ① 候选词发现 | **LLM** | 否，先入 pending | 分析时除抽取已知词外，额外产出 `novel_concepts` |
| ② 候选→正式词 | **LLM 判定 + 阈值** | 高置信自动 / 低置信进 review | LLM 决定维度归属、标量/类别、render 模板 |
| ③ 新耦合规则建议 | **LLM 建议 + 人工审核** | 否，永远需人批 | 规则影响人格，风险高，首期不自动采纳 |

### 11.3 ① 候选发现：让分析器顺手找新概念

在 LLM 抽取的输出里增加 `novel_concepts` 字段：

```json
{
  "observed": [ {"key": "user_mood.frustrated", "intensity": 0.7} ],
  "novel_concepts": [
    {
      "phrase": "社恐",
      "proposed_dimension": "user_personality",
      "kind": "categorical",
      "suggested_label": "性格·内向/社交回避",
      "evidence": "用户说'在人多的场合我就不敢开口'"
    }
  ]
}
```

`novel_concepts` 与主抽取走**同一套校验流程的反面**：主抽取校验"是否在词表内"（白名单），候选则是"明确不在词表内但有价值"。

### 11.4 ② 升级判定：用 LLM 做"该不该收编"

当某个候选在会话中被观察到 `observed_count >= 3`（可在配置调），触发一次**专门的 LLM 判定**，输入是候选的累计证据片段，要求结构化输出：

```json
{
  "verdict": "adopt",                    // adopt | review | reject
  "dimension": "user_personality",       // 可修正用户建议的维度
  "kind": "categorical",
  "label": "性格·社交回避",
  "description": "用户在群体/陌生社交场景下的回避倾向",
  "render_template": "- 用户性格：偏社交回避，陌生场合需要更低的表达压力",
  "base_weight": 0.5,
  "salience": 0.8,
  "confidence": 0.82,
  "reason": "多次在'聚会/开会'相关表述中出现回避信号，非偶发",
  "redundancy_with": ["user_mood.shy"]   // 与现有词重复则提示合并
}
```

**判定护栏**（任一违例 → 强制 `verdict=review`）：

- `verdict=adopt` 且 `confidence >= 0.7` 且 `observed_count >= 3` → **自动收编**进主词表，立即参与后续权重。
- 其余情况 → `status=review`，进入 `keyword_candidates` 待审队列。
- 若 LLM 报告 `redundancy_with` 非空 → 自动降级为 review，由人工决定是否与现有词合并。
- **新维度**首次出现 → 永不自动采纳，必须人工建维度（防止维度无限分裂）。

### 11.5 安全与可回滚

- 候选词在 approve 之前**完全不影响权重**——它只是躺在候选表里。
- 自动收编的词带 `auto_added=true` 标记，并提供 `dla keyword rollback --id <id>` 一键删词并重建受影响会话的权重快照（有证据流水即可全量重算，见 [03 文档 §2.6](./03-数据模型与存储.md)）。
- render 模板必须由 LLM 生成且经过**模板注入校验**：只允许 `{label}` / `{value_text}` 占位符，禁止任意代码或变量，防止提示注入经词库逃逸到 Prompt。

### 11.6 ③ 规则建议（人工审核，不自动）

LLM 可基于"某类用户信号反复出现却无对应 L3 响应"这一现象，建议新耦合规则（含 `when` / `then` 草稿）。这些**只进建议池，需 `dla keyword review --rules` 人工批准**后才写入 `coupling_rules.yaml`。首期不开放规则自动采纳——规则是人格的扳机，错了比漏了更糟。

### 11.7 开源协作的红利

因本项目确定开源，词库演化天然成为**社区贡献入口**：

- 用户跑久了积累的高质量候选/规则，可 `dla keyword export-curated` 导出，提 PR 合入上游词库。
- 这把"一个人的对话习惯"沉淀成"所有人的人格素材库"，是本项目的长期价值主张之一。

### 11.8 词库的向量化与在线学习（独立子系统）

用户在评审中进一步要求：三个词库用**多维 embedding 向量化模型**存储跨层关联；对话中由 LLM **实时增删改**用户/Agent 关键词；当大模型给出更新时，**本地词库模型权重按学习率 + 损失函数**更新；并通过**双反馈回路**使 Agent 越来越贴合用户理想、随满意度收敛。

这部分已从本节的"LLM 候选词 + 审核"扩展为一个独立的子系统，完整设计见 **[06 · 向量化词库与在线学习](./06-向量化词库与在线学习.md)**，核心要点：

- 关键词编码为 d 维向量 `e_k`（冻结），跨层关联由可训练的**双线性矩阵 `M_r`**（多关系头）表示——这是"本地模型权重"。
- LVM 提供 L3 学习先验 `p_agent`，经 §5.2 的 γ 融合进 `w3`；冷启动时可据场景权重**确定性生成 Agent 身份关键字**。
- 每轮 `agent_ops` + `satisfaction` 作为监督信号，对 `M_r` 做**解析梯度 + 学习率**更新（纯 numpy，无 GPU）。
- `add` 复用本节候选→审核流程；`delete`/`update` 是新增的运行期工作集操作，受 §11.5 护栏约束。

> 衔接：§2.6 的证据流水仍是权重重算的基石；doc/06 的回放缓冲与 `lvm_training_log` 是学习过程的可观测性对应物。

## 12. 开场称呼（Greeting）生成

> 用户确认：**开场称呼也要根据预设的场景权重，由模型生成**；当对话刚开始、还没有任何场景权重时，用 `hi` / `你好` 这类默认方式打招呼。

### 12.1 为什么单独设计

称呼是 Agent 的**第一印象**，它应当和场景一致——一个口语练习伙伴的开场和一位严肃面试官的开场不该一样。但"第一印象"发生在**任何用户消息之前**，那时（尤其自动模式下）可能还没有场景权重。所以需要一套"有权重就场景化、无权重就兜底"的生成逻辑。

### 12.2 生成函数

```python
def generate_greeting(state, llm) -> str:
    w1 = resolve_l1(state)                     # §3.3 已解析的 L1 权重
    if not active_weights(w1):                 # auto 模式冷启动，L1 仍为空
        return pick_fallback(GREETING_FALLBACK_POOL)   # 你好 / hi / 嗨（轮询或随机）
    # 场景权重就绪 → 调用模型生成场景感知称呼
    prompt = build_greeting_prompt(w1)         # "你是 L1 描述的对话场景，请生成一句自然的中文开场称呼"
    return llm.complete(prompt, model=DLA_GREETING__MODEL or DLA_LLM__MODEL)
```

要点：

- **固定模式**：会话一开始就加载了场景模板，`w1` 立即就绪 → 直接用模型生成贴合场景的欢迎语（如"你好！我是你的英语口语练习伙伴，想聊点什么？"）。
- **自动模式冷启动**：L1 为空 → `pick_fallback` 回退到 `DLA_GREETING__FALLBACK_POOL`（默认 `你好, hi, 嗨`）。用户开口后，LLM 经 `scene_ops` 逐步建立场景（见 [06 §4.4](./06-向量化词库与在线学习.md)），**一旦 L1 就绪，若 `DLA_GREETING__REGEN_ON_SCENE_CHANGE=true`，称呼可重新生成一次**，完成"从通用寒暄到场景化欢迎"的过渡。
- **自由模式（free）**：用户开场前已提供"场景描述"并经 Bootstrap 播种 L1（见 §3.6），故首轮 L1 即就绪 → 称呼**直接场景感知生成、无需回退兜底**，且从第一条消息起就是贴合场景的欢迎语。
- 称呼生成**失败静默降级**到兜底池（与 D12 一致），绝不阻塞对话或首屏渲染。

### 12.3 与既有模块的衔接

- 称呼是 L1 的**下游消费者**，不反向修改权重；它只在会话首轮（及 auto 模式场景确立时）调用一次，不进入每轮推理主链路，成本可忽略。
- 生成的称呼可作为会话第一条 `messages(role=agent)` 落库，也可仅作界面顶栏展示——取决于交互层（[04](./04-交互层设计.md)）。
- 调试思维链中以 `⓪ 开场称呼` 帧单独展示（含"回退兜底"标记），让"为什么这么开场"同样可解释。
